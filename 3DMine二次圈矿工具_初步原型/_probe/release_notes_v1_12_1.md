## 二次圈矿工具 v1.12.1

### 修复：换矿段后坐标 TXT 拖进去被忽略

现象：把 `3570取样1023.txt` 拖进主界面，日志只回一句

```
拖入 1 个对象：
   （没认出来，忽略）3570取样1023.txt
```

**原因**：识别规则写死了 `BS-` 前缀 —— 文件名里必须带 `BS-` 才当成坐标文件。
中心矿段的取样文件正好不是这套命名：

```
文件名   3570取样1023.txt                       ← 没有 BS-
工程号   zx-3570-1023-p1 … p22                  ← 前缀是 zx-，还是小写
```

而且这条不是孤立的，整条链路三处都认 `BS-`：

| 位置 | 原来 | 现在 |
|---|---|---|
| 拖拽识别（`client/gui.py`） | 文件名含 `BS-` 才算 | **看内容形态**：有一行是「工程号,,E,N,R」五列且后三列是数字 |
| 认平台/日期（`parse_tag_from_txt`） | 文件名里 `BS-(\d+)-(\d{4})` | 先文件名，再读第一行工程号的 `前缀-平台-日期-`，最后按文件名里的数字兜底 |
| 认品位表工程号（`parse_grades`） | 只认 `^BS-` 开头 | 先按"这一格是不是 TXT 里真有的工程号"（不分前缀/大小写），再按工程号形态兜底 |

改完以后 `BS-` / `NS-` / `zx-` 以及以后任何两三四个字母的前缀都能用，
大小写也不敏感（`zx-3570-1023-p1` 会原样保留，不会给你偷偷转大写）。

### 实测中心矿段 3570-1023

| 项 | 结果 |
|---|---|
| 拖拽识别 | ✓ 认出是坐标文件 |
| 平台 / 日期 | 3570 / 1023（从 `zx-3570-1023-p1` 里认的，不是靠文件名） |
| 孔数 | 22 |
| 孔深（取整后） | 3568.192~3569.722 → 9 / 10 m |
| 品位表 | 22 个小写 `zx-…` 工程号 22 个全对上 |
| 生成 .xls / .mdb | 22 行，定位表「最大孔深」、测斜表「深度」、pit_blast「至」都是整数 |

报告类 txt（`BS-3940-1008_报告.txt`）仍然不会被误当成坐标文件。

### 一个提醒：生成的文件名

默认命名还是 `<平台>平台 炮孔数据库<日期>`，平台填 3570 就会生成
`1、3570平台 炮孔数据库1023.xls`；而你 `3570-1023` 目录里已有的是
`1、中心矿段3570平台 炮孔数据库-1023.xls`（带矿段名、日期前有连字符）。

名字不一致时程序**不会**把已有的那份当成冲突去提示覆盖，会并排多出一份。
想对齐的话，在「新建炮孔数据库」窗口里把**平台**改成 `中心矿段3570` 再生成；
或者干脆把旧的那份挪走。
