## 二次圈矿工具 v1.4.1

### 修复：把工具指到"扩展名与真实格式相反"的数据时直接报错

用 v1.4 对**南部山头**那套数据跑「单日数据并入总表」，会在这两栏同时失败：

```
[失败] 炮孔数据报告 (.xlsx)：openpyxl does not support the old .xls file format,
       please use xlrd to read this file, or convert it to the more recent .xlsx file format.
[失败] 炮孔数据库 (.xls)：formatting_info=True not yet implemented
```

**原因**：两套数据的扩展名正好颠倒，而旧代码是"看扩展名选读取库"。

| 数据 | 炮孔数据库 | 综合报告 |
|---|---|---|
| 北部山头 `北部山头<平台>平台2026\` | `.xls`（BIFF） | `.xlsx` |
| 南部山头 `26.09.22南部山头二号矿体\…` | `.xlsx` | `.xls`（BIFF） |

文件名叫 `.xlsx` 其实是 xls → 被 `openpyxl` 拒；文件名叫 `.xls` 其实是 xlsx → 被 `xlrd` 拒。
北部山头一直是"名实相符"的，所以这个坑一直没暴露。

### 怎么修的

**改成读文件头（魔数）判断真实格式**，扩展名完全不参与决策：

* `PK\x03\x04` → 按 xlsx 处理（`openpyxl`）
* `D0 CF 11 E0 A1 B1 1A E1` → 按 xls/BIFF 处理（`xlrd` + `xlutils`）
* 新模块 `src/excel_core/filetype.py`，`sniff()` 一个函数搞定

于是下列组合全部跑通（以前只有第一种）：

| 单日 | 总表 | 以前 | 现在 |
|---|---|---|---|
| xls | xls | ✓ | ✓ |
| xlsx | xlsx | ✗（崩） | ✓ |
| xls | xlsx | ✗（崩） | ✓ |
| xlsx | xls | ✗（崩） | ✓ |

配套改动：

* **数据库**（`db_xls.py`）：xlsx 总表用 `openpyxl` 原地追加，样式沿用最后一行，其余工作表不动；
  BIFF 总表仍走 `xlutils` 整体复制，保真不变。
* **综合报告**（`report_xlsx.py`）：目标总表是 `.xls` 时，块追加到第一张表（南部山头就是「每日」），
  值/公式/合并单元格都带上；样式改为**借总表里同类行**（标题、表头、小计、合计、明细各借各的），
  视觉与既有报告块一致。
* **合计自检**：两种源格式都能查。
* **报告标题识别**：南部山头写成「…炮孔数据库报告…」「…矿块报告…」，一并认了
  （原来只认「炮孔数据报告」）。单日报告的文件名匹配也放宽到这两种叫法。
* **工程号前缀**：原来只认 `BS-`，现在 `NS-` 等两三个字母的前缀都认（影响复核里的分段统计）。

### 一个副作用，需要知道

xlsx 总表（南部山头 `1、…炮孔数据表.xlsx`）里有公式列，例如 `每日坐标` 的 `=D1-3960`（108 个）。
**Excel 格式保存时，公式的缓存值会被清空** —— 公式本身还在，文件也设了"打开时重算"，
用 Excel 打开保存一次即可恢复。

影响只在"**不开 Excel 直接读缓存值**"的场景（第三方工具/脚本按值读取）。
真遇到时日志里会明确提示：

```
[提示] 总表是 xlsx，里面有 108 个公式单元格（如「每日坐标」的 =D1-3960）。…请先用 Excel 打开保存一次。
```

BIFF（.xls）总表没有这个问题，缓存值原样保留。

### 怎么用

南部山头那套现在可以直接跑（目录结构一致，自动识别）：

```bat
python excel_tools\main.py --daily --day-dir "…\南部山头3970平台-2026\7、单日数据\南部山头3970平台-0719" --dry-run
```

去掉 `--dry-run` 才真写。界面上操作完全一样：主界面 →「Excel 工具」→「单日数据并入总表…」。
窗口标题会显示 **v1.4.1**，改了代码请关掉旧窗口再重启。
