## 二次圈矿工具 v1.13

### 修复：炮孔报告汇总按矿段换品位分级

现象：中心矿段的报告汇总出来"少一档"。人工成果是
`0.500-0.800 / 0.800-1.000 / 1.000-999.000` 三档，程序出来的却是
`0.500-1.000` 一档 —— 品位 0.55 / 0.75 / 0.90 全被并进去了。

**原因**：报告汇总的档位区间写死成金斗山那一套：

```python
# src/blast_report/schema.py（修复前）
GRADE_BANDS = ((0.0, 0.5, "0.000-0.500"),
               (0.5, 1.0, "0.500-1.000"),
               (1.0, 1.5, "1.000-1.500"),
               (1.5, 3.0, "1.500-3.000"),
               (3.0, None, "3.000-999.000"))
```

`by_total.py` 的档位反推直接调 `band_of_grade()`，跟"选的哪个矿段"毫无关系 ——
所以中心矿段的数据也按金斗山的边界切，换矿段就必错。

### 现在：分级进配置，汇总时按当前矿段取

| 矿段 | 档位 | 工业品位下限 |
|---|---|---|
| 金斗山（北部山头 3940/3960） | `0.000-0.500` / `0.500-1.000` / `1.000-1.500` / `1.500-3.000` / `3.000-999.000` | 0.0 |
| 中心矿段（3550~3640 平台） | `0.500-0.800` / `0.800-1.000` / `1.000-999.000` | 0.5 |

* 分级放在 **`excel_tools/config/grade_profiles.json`**，改档位/加矿段只动这个文件，
  不用改代码；配置文件丢了或写坏了会回落内置那份并在日志里告警，不会崩。
* 档位名按分界值自动生成（`0.500-0.800` 这种写法与 3DMine 报告完全一致），不用手写。
* **边界规则统一为「下限含、上限不含」**：`0.500` 归 `0.500-0.800`，`0.800` 归 `0.800-1.000`。
  相邻档共用同一个分界值，所以既不会重复计数也不会留缝（自检里逐 `0.001` 扫过全区间）。
* 低于工业品位下限的品位**单列 `<0.500` 一档排在最后**并告警，不再偷偷并进最低档。

**用哪套分级**（日志里打 `[分级] …（依据）`，窗口里也能选）：

| 优先级 | 依据 | 例子 |
|---|---|---|
| 1 | 手动指定 | 界面下拉框选「中心矿段」/ `--grades center` |
| 2 | 路径关键字 | `…\中心矿段2026\中心矿段3570平台\…` |
| 3 | 源报告里的档位名 | 报告里出现 `0.500-0.800` |
| 4 | 配置里的 `default` | 认不出来时用金斗山（与旧行为一致，不影响老数据） |

### 顺手修掉的一个串味标题

`naming.guess_title()` 原来只会判"平台标签是不是以 `北部山头` 开头"，
所以中心矿段的路径会拼出 **`北部山头中心矿段3570平台1023炮孔数据报告`**。
现在按分级配置里的矿段名判断，已经是 `中心矿段3570平台1023炮孔数据报告`；
南部山头的路径也不会再被加上"北部山头"。

### 实测（中心矿段 3570-1023 真实报告，总计品位 0.8177）

| 分级 | 落档 |
|---|---|
| 修复前（金斗山） | `0.500-1.000` ✗ |
| 修复后（中心矿段） | `0.800-1.000` ✓ |

同一批数据在金斗山分级下仍然落 `0.500-1.000`（老数据按老口径），
所以金斗山的历史成果一格都没变。

### 验收

`excel_tools/tests/test_grade_profiles.py` **48/48 全过**：

* 两套分级的档位名与边界归属（含 `0.500` / `0.800` / `1.000` 归哪档）；
* 逐 `0.001` 扫 `0.000~5.000`，确认档位不重叠、下限以上不漏档；
* 矿段识别：路径关键字 / 源报告档位 / 手动指定，三种都认；
* 同一批中心矿段数据（0.55 / 0.75 / 0.90 / 2.40，4 个矿块）在**两套分级**下各汇总一次，
  逐格比对档位、体号重编、同档内顺序、合计体积/重量/金属量；
* 低于下限单列 `<0.500` 并告警；配置损坏/缺失回落内置分级；
* 本机有真实中心矿段报告时，核对配置档位与报告里写的三档一致。

`test_locks.py` 13/13（`test_merge.py` / `test_daily_merge.py` 依赖本机
`D:\WK\N CRT\` 下的真实数据，换机器时按原样跳过）。
