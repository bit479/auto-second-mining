## 二次圈矿工具 v1.14

### 修复：二次圈矿也按矿段换品位分级

v1.13 把**炮孔报告汇总**的档位改成按矿段取，但真正出矿块图的**二次圈矿链路**还留着写死的金斗山档位。
换到中心矿段（3550~3640 平台，档位是 `0.5-0.8 / 0.8-1 / ≥1`，只有三档）时：

* 0.85 的孔本该单独一档，却被并进 `0.500-1.000`；
* 块分层、图上图层、报告里的档位名、孔数统计列，全都按四档出；
* 但报告汇总那条已经按三档出了 —— 两条链路对不上。

**根因**：档位散在十来个文件里写死。

| 位置 | 原来 |
|---|---|
| `core/oreblocks.py` | `LEVELS = [("L4",3.0,inf,…), ("L3",1.5,3.0,…), ("L2",1.0,1.5,…), ("L1",0.5,1.0,…)]` |
| `core/autoblock.py` | `for lid, _, _, _ in (("L4",3.0,9e9,…), ("L3",…), ("L2",…), ("L1",…))` |
| `core/strip.py` | 三处同样的四元组 + `order = {"L4":0,"L3":1,"L2":2,"L1":3}` |
| `core/deliver.py` | `level_id_of()` 里一串 `if grade >= 3.0: return "L4"`；图层名/色号表；孔数统计列 |
| `core/run_batch.py` | `COLORS` / `LV_TXT` 四档常量 |
| `core/merge_to_composite.py` | `LAYER_COLOR = {"0.500-1.000": 4, …}` |
| 各处 | 废孔阈值写死 `0.5` |

### 现在：档位只有一份配置、一个入口

新增 **`core/grades.py`** —— 圈矿链路里档位的唯一来源，读的是
**`excel_tools/config/grade_profiles.json`**（与 v1.13 的报告汇总**共用同一份**，
`_probe/test_grades.py` 里有一项专门核对两边分界值一致，防漂移）。

| 矿段 | 圈矿档位 | 工业品位下限 |
|---|---|---|
| 金斗山（北部山头 3940/3960） | `0.5-1` / `1-1.5` / `1.5-3` / `≥3`（**四档**） | 0.5 |
| 中心矿段（3550~3640 平台） | `0.5-0.8` / `0.8-1` / `≥1`（**三档**） | 0.5 |

* 配置里新增键 `ore_cutoff`：**圈矿**用的工业品位下限。金斗山填 `0.5` —— 它的
  `0.000-0.500` 只是"报告汇总"里的废石档，圈矿里不算一个档位，所以圈矿档位仍是四档，
  老成果一格不变。低于 `ore_cutoff` 的孔照旧是废孔（`grades.cutoff()`，不再各处写 `0.5`）。
* 档位 id 按品位从低到高编号：金斗山 `L1~L4`、中心矿段 `L1~L3`；
  体号仍按高档在前（`grades.order_map()`），颜色仍按位置（青/蓝/红/黄）。
* 档位名由分界值生成（`0.500-0.800`），图上图例用短标签（`0.8-1`、`≥1`），
  整块废石仍标 `<0.500`（`L0`）。
* 边界**下限含、上限不含**，相邻档共用分界值 —— 不重叠、不留缝。

**用哪一套**（日志第二行会打 `[分级] …（依据）`）：

| 优先级 | 依据 |
|---|---|
| 1 | 界面上的「矿段（品位分级）」下拉（默认"自动（按路径认）"） |
| 2 | 命令行 `--grades auto|jindoushan|center` |
| 3 | `圈矿参数.json` 的 `mine_section`（可按平台/炮区覆盖） |
| 4 | 路径关键字：数据库/综合图/输出目录里带 `中心矿段` 或 `zx-` → 中心矿段；否则金斗山 |

### 改动的文件

| 文件 | 改动 |
|---|---|
| `core/grades.py` | **新增**，档位/识别/图层名/短标签/色号/体号排序的唯一入口 |
| `excel_tools/config/grade_profiles.json` | 加 `ore_cutoff` 键（报告汇总不受影响） |
| `core/oreblocks.py` | 删掉 `LEVELS` 常量，`level_of()` 转调 `grades`；废孔阈值用 `grades.cutoff()` |
| `core/autoblock.py` / `core/strip.py` / `core/pipeline.py` | 四元组循环 → `grades.ids_desc()` / `grades.levels_desc()` / `grades.order_map()` |
| `core/deliver.py` | `level_id_of()` 转调；DXF 图层/层名按当前档位生成；孔数统计列按当前档位生成 |
| `core/run_batch.py` | 柱状图颜色/图例、矿孔判定按当前档位；每个单日目录各认一次矿段；`--full` 把 `--grades` 传下去 |
| `core/merge_to_composite.py` | 层名→色号/颜色按当前档位；`main()` 先认矿段 |
| `core/run_strip.py` | 解析 `--grades`，开跑前认矿段并打 `[分级]` |
| `core/params.py` | 新增默认参数 `mine_section: "auto"` |
| `client/gui.py` | 多一行「矿段（品位分级）」下拉，并把选择传给三个子进程；版本号 v1.14 |
| `_probe/test_grades.py` | **新增**，36 项自检 |
| `_probe/accept_all.py` | 加了第 ⑨ 项 |

### 注意

* 一次批量里如果混着两个矿段的数据，**每个单日目录会各认一次矿段**（不会串档）。
* `src/` 里那套旧 PoC（根目录 `main.py`）和 `client/prep_generic.py`、`client/make_dwg_generic.py`、
  `client/render_preview.py`（老客户端 `二次圈矿工具客户端.py` 用的）**不在"一键出三件套"链路上**，
  仍是写死的金斗山档位。要用中心矿段请走 `启动二次圈矿工具.bat`（`client/gui.py`）这条链。
* 升级时 `excel_tools\config\grade_profiles.json` 要一起带走 —— 它现在是两条链路共用的档位配置。
