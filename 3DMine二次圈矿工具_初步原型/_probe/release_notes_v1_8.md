## 二次圈矿工具 v1.8

### 单日数据并入总表：先查文件是不是还开着

以前并入前不管文件有没有被 Excel / Access / 3DMine / AutoCAD 打开，于是有两种翻车方式：

* **总表开着** → 写不进去，或者写到一半报错；
* **单日文件开着**（更要命）→ Excel 里改了没保存，磁盘上还是**旧内容**，
  并进去的是旧数据，而且事后完全看不出来。

现在并入前会先查一遍，发现占用就**当场中止**，一行都不写、连备份都不做：

```
[中止] 以下文件还开着（或没有写权限），现在并入会失败或读错数据：
  · [总表] 1、北部山头3940平台 炮孔数据库-2026.xls
        位置：E:\AAAWK\2026地质生产数据\北部山头2026\…\1、…xls
        原因：被其他程序占用（Excel / Access / 3DMine / AutoCAD 打开着）

请先在 Excel / Access / 3DMine / AutoCAD 里**保存并关闭**这些文件，然后重新运行。
（确认没有未保存的修改后，也可以用 --allow-open 强行继续）
```

**怎么判的**

| 手段 | 说明 |
|---|---|
| 写探测 | `os.open(路径, O_RDWR)` 打不开 → 被占着写权限。只开关、不写一个字节，对文件零影响 |
| 锁文件 | Excel 留 `~$<文件名>`、Access 留 `<文件名>.ldb`、CAD 留 `<文件名>.dwl` / `.dwl2`，作辅助证据 |

* 写探测失败 → 中止（上面那样）；
* 只有锁文件、但文件能写 → 判为"程序崩溃留下的残留锁"，**不拦**，只提示一句：
  `[提示] 1 个文件旁边有残留锁文件，但文件本身可写，判定为已关闭：…`
* `--dry-run` 预演只提示不中止；
* `--allow-open` 可以硬闯（确认没有未保存改动时用）；
* **还原备份**（`--restore`）同样会先查 —— 它要覆盖总表，被占用会失败。

> 为什么不做"自动保存并退出"：本机没有 Office COM（pywin32 未装），
> 强行结束 Excel / Access 进程有丢数据的风险。宁可拦下来让你自己保存关闭。

### 界面

单日并入页多一个默认勾选的选项：

> ☑ 并入前检查文件是否已保存并关闭（Excel / Access / CAD 占用就中止）

取消勾选 = 命令行加 `--allow-open`，只提示不中止。

### 验收

新增自检 `tests/test_locks.py`（**13 项，全过**），用 `CreateFileW(share=0)` 模拟
"被 Excel 独占"，不依赖真的开 Office：

1. 普通文件 → 不拦；
2. 独占打开 → 拦住，原因写明"被其他程序占用"、报告带文件名；
3. 只有 `~$` 残留（文件能写）→ 判残留，不拦；
4. 只有 `.ldb` 残留 → 同上；
5. 同一路径传两次只报一条；
6. 提示文字含"保存并关闭"与 `--allow-open`。

另外用真实数据在沙箱里走了一遍完整流程：

| 场景 | 结果 |
|---|---|
| 锁住总表 `.xls` + `--dry-run` | 一行提示，预演照做 |
| 锁住总表 `.xls` + 正式并入 | **退出码 3**，中止，**没有生成任何 .bak** |
| 释放锁后正式并入 | 正常完成，`exit 0` |
| 只有 `~$` 残留 | 提示一句，正常完成 |
| 锁住 `.mdb` + `--restore` | 中止，提示"还原会覆盖这些总表" |
| 锁住 `.mdb` + `--allow-open` | 放行，`.mdb` 那栏报"打开数据库失败，请关闭后重试" |

原有四套自检全过：14/14、全过、35/35、26/26。`跑验收.bat` 里的「Excel 工具自检」从 4 项变 5 项。

### 怎么用

不用改习惯 —— 照旧跑 `--daily`，被占用时会告诉你关哪个文件：

```bat
python excel_tools\main.py --daily --day-dir "…\7、单日数据\北部山头3940平台-1008" --dry-run
```

窗口标题显示 **v1.8**，改了代码请关掉旧窗口再重启。
