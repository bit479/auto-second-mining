# 二次圈矿工具 · 项目结构说明（交接用）

> 这个工具做的事：**丢给它两个文件（炮孔数据库 Excel + 该平台综合图 DWG），
> 一键出三件套**——炮孔数据报告、二次圈矿矿块图（DWG 2010）、矿块边界线 .3ds。
> 算法口径全部写在 **`口径确认记录.md`**，那份是"以用户为准"的唯一依据。

## 一、怎么跑

双击 **`启动二次圈矿工具.bat`**（无控制台窗口），界面就四行：① 炮孔数据库 Excel
② 综合图 DWG ③ 平台/日期 ④ 输出目录，然后按需要点：

| 按钮 | 作用 |
|---|---|
| **一键出三件套** | 圈矿 → 报告 xlsx/png → 矿块图 DXF →（勾选）DWG 2010 →（勾选）并入综合图副本+预览 |
| **批量跑整个目录…** | 选一个"里面每个子目录是一天炮区"的父目录，一次跑完并出汇总 |
| **并入综合图（副本）…** | 把某天的边界线 .3ds 并进综合图的**副本**（原件不动），出预览图 |
| **确认替换综合图原件…** | 弹窗确认后：原件改名备份 → 副本顶上；可一键回退 |
| **用人工图标定本炮区…** | 给一张人工圈矿图，自动标定该炮区的外推距离与左右链，写进参数 |

命令行等价（全部在 `core\` 下）：

```
python core\run_strip.py "<数据库.xls>" 3940 <日期> "<输出目录>" "<综合图.dwg>"
python core\run_batch.py  "<父目录>"    "<综合图.dwg>" "<输出目录>" [--full]
python core\dxf2dwg.py    "<…矿块图.dxf>"
python core\merge_to_composite.py "<综合图.dwg>" "<…矿块边界线.3ds>"
python core\apply_merge.py "<…_并入1008.dwg>" [--dry-run]
python core\calibrate.py <日期> "<人工圈矿图.dwg>" [--extrude 3 4 5] [--by-volume] [--write]
python core\merge_status.py "<父目录>" "<综合图.dwg>"      # 哪些炮区还没并进综合图
python _probe\selftest.py                                   # 验收自检（改代码前后各跑一次）
```

## 二、目录结构

| 路径 | 内容 |
|---|---|
| `client\` | GUI（`gui.py`）+ 图标。`启动二次圈矿工具.bat` 启动它 |
| `core\` | **全部核心逻辑**：`pipeline.py`（一个炮区的完整流程）、`strip.py`（矿界）、`gradecuts.py`（品位界限）、`deliver.py`（报告/图/.3ds）、`params.py`（参数）、`composite.py`（综合图）、`oreblocks.py`（读库与算量）、`dxf2dwg.py`、`merge_to_composite.py`、`apply_merge.py`、`calibrate.py`、`run_strip.py`、`run_batch.py`、`merge_status.py` |
| `_probe\` | **验收与标定用**（保留 17 个）：`selftest.py`（验收闸门）、`compare_manual_auto.py`（人工 vs 自动对照出图）、`review_batch.py`、`review_1008.py`、`tune_blocks2.py`、`tune_chains.py`、`scan_manual_retry.py`（只读扫描人工图）、`render_dxf_png.py`、`composite_scan.json`、`manual_09xx/10xx_c.json`（5 张人工图的扫描结果 = 验收基准） |
| `sample_data\output\` | 最近的评审图：`对照_<日期>.png`（人工 vs 自动）、`回归_自动圈矿_*.png` |
| `归档\` | 一次性调试产物与旧流程输出（可删） |
| `口径确认记录.md` | **所有已确认口径**（算量、矿界、分块、参数、依据） |
| `使用说明-一键出三件套.md` | 操作手册（输入、产出、参数、故障提示、回归脚本） |
| `圈矿参数.json` | 按平台生效的参数（外推、连接半径、最小块段、链、容重…） |

## 三、验收基准在哪、怎么复现

5 个炮区的人工圈矿图扫描结果在 `_probe\manual_<日期>_c.json`（只读扫出来的块轮廓 +
炮孔文字），人工报告的合计体积写在 `_probe\selftest.py` 的 `MANUAL_VOL` 里。

跑 `python _probe\selftest.py` 会打印：

| 炮区 | 矿界 IoU | 体积 | 人工 | 差 |
|---|---|---|---|---|
| 1008 | 0.929 | 3874.0 m³ | 3951.5 | −2.0% |
| 0915 | 0.923 | 13283.7 | 13497.3 | −1.6% |
| 1003 | 0.911 | 9376.7 | 9435.0 | −0.6% |
| 1004 | 0.805 | 9859.3 | 9846.4 | +0.1% |
| 0922 | 0.624 | 6869.5 | 7075.3 | −2.9% |

达标线：1008 IoU ≥0.90 且体积 ±5%，其余 IoU ≥0.75 且 ±20%；退出码 0 = 全绿。

## 四、新人上手三步

1. 读 `口径确认记录.md`（口径）→ 读 `使用说明-一键出三件套.md`（操作）；
2. 跑 `python _probe\selftest.py` 确认环境正常（应当"全部达标 ✓"）；
3. 拿一个**新炮区**试：把它的数据库和人工图丢给 `core\calibrate.py` 标定一次，
   再跑 `run_strip.py`，用 `_probe\compare_manual_auto.py` 出对照图核对。

## 五、改代码的规矩

* 任何算法改动，**先跑 `_probe\selftest.py`**，全绿再提交；退化就退回来；
* 口径有疑问或不确定 **先问用户**，不要自己拍数值（本项目的所有阈值都是拿人工图标定出来的）；
* 真实矿山数据（`北部山头3940平台2026\`）只读、不挪不改；综合图只用 AutoCAD 只读扫描。
