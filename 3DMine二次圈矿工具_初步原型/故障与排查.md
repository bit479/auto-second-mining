# 故障与排查（症状 → 先看哪儿 → 怎么办）

> 遇到问题先别猜，按下面的顺序走。**所有排查都在本机就能做完，不需要改代码。**

## 〇、起手三件事

| 步骤 | 做什么 | 看什么 |
|---|---|---|
| 1 | 打开成果目录里的 **`运行记录.txt`** | 运行时间、耗时、**当时生效的全套参数**、产生的文件清单、完整日志——出问题直接看它 |
| 2 | `python _probe\accept_all.py --quick`（或在 GUI 点"快检"） | 是**环境问题**（连基准炮区都跑不通）还是**只这一个炮区**的问题 |
| 3 | `python _probe\params_report.py <平台>`（或 GUI"查看参数台账"） | 参数是不是被覆盖成了怪值（外推、贴合、模式、链、孤立组孔数） |

还有一句能省很多时间的：**`验收报告.md`** 是最近一次全量验收的自动报告（带代码版本），
你改过东西之后先看它有没有变红，再决定要不要动别的地方。

## 一、跑不起来 / 输入类

| 症状（日志里的话） | 先看哪儿 | 怎么办 |
|---|---|---|
| `[错误] 找不到炮孔数据库：…` | 路径里有没有中文空格被吃掉、文件是不是被移动 | 在 GUI 里用"浏览…"重选，别手打路径 |
| `[错误] 炮孔数据库应当是 .xls/.xlsx，收到的是：…` | 选的到底是不是 Excel | 正常流程只吃**导出后的 Excel**；`src\mdb_loader.py` 是早期 PoC 里直读 mdb 的模块，**没有接进现在的流水线**（`core\` 里没人 import 它）——要直读 mdb 得先接 |
| `打不开这个 Excel（…）：…` | Excel 是不是开着这份文件、有没有密码 | 关掉 Excel 再跑；有密码的要先解密 |
| `数据库缺少工作表：定位表/pit_blast` | 表名被改过？ | 用 3DMine 原样导出的库（表名固定这两个） |
| `定位表第 N 行读不动…` / `pit_blast 第 N 行的 Au 不是数字…` | 那一行是不是空行、合并单元格、或写了"0.5~1"这种区间 | 在原表里改干净（空行删掉、区间拆成数值） |
| `[错误] 认不出日期（炮区号）` | 文件名里有没有 4 位炮区号 | GUI 里手工填平台/日期（自动识别只是方便） |
| 拖进去没反应 | 装没装 `tkinterdnd2` | `pip install tkinterdnd2`；没装就用各栏的「浏览…」按钮（其它功能不受影响） |
| 拖进来的 `.dwg` 跑到综合图栏去了 | 文件名里带"综合"就会被当综合图 | 人工圈矿图的名字一般形如 `…二次圈矿矿块图1011.dwg`，不含"综合"，会被认成人工圈矿图；实在认错就手工用「浏览…」选 |
| **图上的矿界不是我圈的那条线** | 先看成果目录里的 `运行记录.txt`，看 `outline_files` / `manual_blocks` 是不是空的 | 空的就是**没走人工画线**——那时程序自己圈的界。现在（v1.2.1 起）填了 .3ds 却选「① 自动圈矿」会**弹窗提醒并帮你切模式**；也可以直接在"圈矿模式"里选 ②/③ |
| 图上还画着综合图那一片灰线 | v1.2.1 起默认不画了 | 想留参照才需要它；成果图默认只画当日矿块（人工画线模式下连"并进历史块"也关掉，保证图就是你画的那条线） |
| `[错误] 没圈出任何矿块` | 品位是不是全 <0.5、或者坐标列反了 | 先 `params_report` 看 `zone_link_m`；坐标反了要在库里纠正（E/N 列） |

## 二、圈矿结果不对

**先分清是"规则"还是"参数"问题**：跑一次 `python _probe\dxf_check.py <平台> <炮区> --fresh`
（图上要素是否合规）和 `python _probe\selftest.py <平台>`（这个炮区相对人工图差多少）。

| 症状 | 先看哪儿 | 怎么办 |
|---|---|---|
| 日志出现 **`[矿界自检] N 个矿孔原本落在矿界外（…）`** | 是哪些孔、在哪一端 | 说明闭合那一段没包住孔，程序已用"廊道"补上（能出成果但要复核）。若频发：该炮区多半是"紧凑孔簇/端头单排"——把 `end_pair_beyond`、`extrude_m` 或分簇方式标定一次（见"标定"一节） |
| **块数**跟人工图差很多 | 人工图里有几块、自动几块 | `clusters` 模式用 `cluster_exact` 按人工图逐块指定孔组；`chain` 模式看 `min_fragment_m2`（默认 40 m²） |
| **体积**差得多（>10%） | 是外推太大/太小，还是把综合图的大块吞进来了 | 改 `extrude_m`；`seam_join_m` 关到 0（贴合会吸进历史块窄条，体积会变大）；用 `_probe\_calib_strict*.py` 扫一遍再定 |
| 矿界形状"怪"/带尖刺 | 是不是 `chain_right/chain_left` 里塞了不该进的孔 | 跑 `python _probe\params_report.py <平台>` 看是哪个炮区被人工指定过，再 `_probe\_review_one.py <平台> <炮区>` 出对照图 |
| 某个矿孔"孤零零"没被圈 | 它与主带距离 > `zone_link_m`(15 m) | 正常行为（列"缺工程待取样"）；要圈就把 `zone_link_m` 调大或把它并进 `cluster_same` |
| 综合图那块"贴不上" | 日志 `[提示] 综合图没读到历史块` | 见下面第四节 |

**标定一个新炮区**（比手改参数稳）：

```
python core\calibrate.py <炮区> "<人工圈矿图.dwg>" --platform <平台> --extrude 3 4 5 --by-volume --write
```

它自己会找同目录的数据库与综合图，扫人工图（AutoCAD 只读）、搜"外推 + 左右链"，
`--write` 才落盘（写进 `圈矿参数.json` 的 `blasts["<平台>-<炮区>"]`）。

## 三、出图/图上要素不对

先跑 **`python _probe\dxf_check.py <平台> <炮区> --fresh`**，它会把 9 项逐条打勾/打叉，
下面是对应关系：

| 它报的项 | 含义 | 怎么办 |
|---|---|---|
| 图名 / 十字 / 引线 / 工程号 / 品位 / 方格 / 网格小字 | 见 `README.md` 的判据 | 基本都取决于 `core\deliver.py` 的常量（十字半臂 0.5、引线 1.2、工程号色 138…），**改常量前先问用户** |
| `工程号与数据库逐条一致 → 缺 XX` | 图上写的和库里不一样 | 多半是**数据库自己的工程号**跟文件夹日期不同（例：3960-0908 的库里是 `BS-3960-0907-*`）——这是数据事实，不是 bug |
| `矿块号不压矿块 / 互不重叠 / 不压报告图` | 标注压到东西了 | 标注避让在 `deliver.py`（会避开矿块、**合并后轮廓**、报告图、图名、其它标注）；块特别多/特别歪时可能兜底到不理想的位置，加人工微调或改避让盒大小 |
| `方格边长≈1 m（被裁格 x%）` | 边界把格子裁掉了 | 人工图自己也有 10.7~14.9% 被裁格；超过 20% 才是问题（多半是矿界形状异常） |
| `报告图（IMAGE）0 张` | 报告 png 没插进去 | 看 `run_strip` 日志里 `报告图片已插入` 那行；png 生成失败一般是 matplotlib 中文字体问题 |
| 图里中文显示成**问号** | 字体 | 输出用的是 `CN_TTF`(simsunb.ttf)；在 CAD 里若仍显示问号，检查该字体是否可用，或让用户指定字体 |
| **DWG 转换失败**（日志 `[失败] 第 2 步 …`） | AutoCAD 没开 / COM 忙 / 弹了对话框 | 保留的 DXF 可以直接用；在 CAD 里手工"另存为 2010"即可；或在 GUI 里取消勾选"转 DWG 2010" |

## 四、综合图相关

| 症状 | 原因 | 怎么办 |
|---|---|---|
| `[提示] 综合图没读到历史矿块`（照常出成果） | ① 那张图里确实没有历史块 ② AutoCAD 没开/正忙，COM 拒绝呼叫 | 把 AutoCAD 打开并**切到空闲**（别停在命令或对话框里）再跑；扫描结果会缓存成 `<综合图名>_scan.json`，下次直接复用 |
| 改了综合图但程序还用旧结果 | 缓存 | 删掉同目录的 `<综合图名>_scan.json` 再跑（只读扫描，不会改图） |
| 想确认哪些炮区还没并进综合图 | — | `python core\merge_status.py "<父目录>" "<综合图.dwg>"` |
| 并入副本失败 / 想回退 | — | "并入"只写**副本**（`…_并入<炮区>.dwg` + `_预览.png`），原件从不动；"确认替换原件"前会自动备份（`apply_merge.py`，支持 `--dry-run` 先看要改什么） |

**安全边界**：`北部山头3940平台2026\`、`北部山头3960平台2026\` 里的真实数据**只读**；
任何"写回去"的操作都先出副本、并要人工确认。

## 五、验收/开发类

| 症状 | 先看哪儿 | 怎么办 |
|---|---|---|
| `accept_all.py` ① 圈矿闸门红了 | 打印的表格里哪一行带 `← 未达标` | 那一行就是退化点；`git log` 找最近改动，或 `git diff` 看代码；必要时 `git revert` |
| ② 报告口径：`某块 口径不自洽` | 该块的 体积/重量/容重/品位/金属量 | 说明写报告那步算错了（`deliver.py` 的体积×容重、重量×品位÷100）；修完重跑 |
| ② 报告口径：合计偏差突然变大 | 该炮区的矿界/分块 | 八成是圈矿侧变了（看 ① 的同一炮区是否也变了） |
| ③ 成果图实体自检红了 | 它逐项打印的 ✗ | 按第三节对应关系处理 |
| ④ 精确模式自检红了 | 人工四段 .3ds 还在不在桌面 | 换了机器/文件被移走就会失败（脚本会提示"样例文件不在桌面，跳过"） |
| 严格档数字很难看 | 不是故障 | 严格档把"综合图里当日本身的块"排掉了（模拟新炮区），分数天然低，只作参考 |
| 只是想确认"我没改坏东西" | — | `python _probe\accept_all.py` 全绿即可；跑完把 `验收报告.md` 留着 |

## 六、把现场材料留给别人

出问题时把这四样一起给人（不用解释太多）：

1. 成果目录里的 **`运行记录.txt`**（含当时参数与完整日志）；
2. **`验收报告.md`**（最近一次全绿/变红的证据，带代码版本）；
3. 出问题那张图（DXF 或 PNG 截图）；
4. `git log --oneline -5`（最近改了什么）。

需要改参数时，**先跑 `params_report.py` 看这个炮区现在被覆盖成什么**，改完再跑
`accept_all.py` 确认没把别的炮区带坏。
