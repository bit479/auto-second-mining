## 二、全局拖放的实现机制

### 2.1 为什么用「应用级事件过滤器」

Qt 的拖放事件只会送给**鼠标下方那个控件**（或它最近的可接收父控件）。如果给 10 个页面
分别加 `dragEnterEvent/dropEvent`，既要改 10 处，又会被页面里已有的 `FileRow`
（本来就支持拖 xls/dwg）抢走事件。

做法：

1. 主窗口 `setAcceptDrops(True)` —— 这一句让 Qt 向 Windows 注册本窗口的 **OLE 放置目标**，
   否则系统根本不会发拖放消息；
2. `GlobalFileDropManager` 作为 **`QApplication` 的事件过滤器** 拦截
   `DragEnter / DragMove / DragLeave / Drop` —— 过滤器比任何页面控件都先拿到事件，
   所以停在哪一页、停在哪个控件上都能接住；
3. **只吃单个 `.txt` / `.dat`**：其它类型直接放行，页面里既有的文件输入行照常工作；
   若指针正停在显式接受拖放的控件上，连"不支持"的提示都不弹，避免干扰原有交互。

### 2.2 一套文件只处理一次

| 场景 | 处理 |
|---|---|
| 同一次拖放被系统重复投递 | `Drop` 时清空 `_drag_path`，第二次 Drop 直接忽略 |
| 同一文件再次拖入（内容未变） | 比较 `路径 + 大小 + 修改时间`，命中就复用上次任务、**不重新解析**，只跳回页面 |
| 解析中又拖入另一个文件 | 记为"待处理"，当前解析结束后自动接着导入（后来的优先），不打断当前解析 |
| 一次拖入多个文件 | 拒绝并提示"一次只能导入一个 TXT" |
| 拖入非 TXT | 不消费事件，交给页面原有逻辑；无落点时才提示"只支持 .txt" |

### 2.3 线程与取消

* 解析在 `QThreadPool` 里跑（`QRunnable`），主线程只收信号 → 6 万行 0.6 秒也不卡界面；
* 解析中按 `Esc`、或点页面上的「取消本次导入」，会置取消位（`threading.Event`），
  解析函数每 2000 行检查一次并抛 `ParseCancelled`；
* 取消后迟到的解析结果会被丢弃（`job.is_cancelled()` 判定），不会突然跳页。

### 2.4 提示层（`components/drop_overlay.py`）

| 状态 | 表现 |
|---|---|
| 拖入中 | 窗口压暗一档 + 2px 虚线框 + 居中 560×78 卡片（上传图标 + "松开鼠标，导入 TXT 坐标文件" + 文件名） |
| 解析中 | 右下角小卡片"正在解析坐标文件…（Esc 可取消）" |
| 成功 | 右下角绿色小卡片：孔数 / 平台 / 日期 / 文件名，5.2 秒自动消失 |
| 失败/有问题 | 右下角红色小卡片，7 秒自动消失 |

覆盖层 `WA_TransparentForMouseEvents`，不抢焦点、不挡点击；结果卡片固定在右下角，
避开各页面左侧/中部的主操作按钮。

## 三、TXT 解析规则

### 3.1 已核对的真实样本

`excel_tools/_out/format_test/平台/7、单日数据/南部山头3970平台-0719/NS-3970-0718-P1-P90.txt`

```
NS-3970-0718-P1,,470163.884,4349418.489,3971.508
（CRLF、逗号、第 2 列为空、无表头、UTF-8）
```

核心脚本 `core/make_database.parse_txt()` 的硬要求是 **UTF-8 + 逗号 + ≥5 列，第 3/4/5 列是数字**，
GBK 会被 `errors="replace"` 读成乱码。因此本功能把"容错读入"和"给核心喂数据"分开。

### 3.2 解析步骤

| 步骤 | 规则 |
|---|---|
| 编码 | `UTF-8(BOM) → UTF-8 → GBK → GB18030` 依次严格解码；含替换字符/控制字符过多的结果判为失败再换下一种 |
| 分隔符 | 制表符 → 逗号（含全角）→ 分号（≥3 个）→ 空白，按首个数据行判定，并在界面标注 |
| 表头 | 首行若含「工程号 / 孔号 / 编号 / 名称 / hole / id / name」或整行无数字 → 视为表头；再按 E/N/R 关键字映射列 |
| 元数据行 | `平台：3940`、`炮区日期：1008`、`台阶高度：12`、`备注:` 等行整行跳过，不当作炮孔 |
| 列映射 | 无表头时：第 1 列 = 工程号，其后**前 3 个数字** = E / N / R（正好兼容 `工程号,,E,N,R` 与 `工程号 E N R`）|
| 多余列 | 保留在 `raw_cells/extras` 里，只提示"多出的列保留原样"，不擅自解释 |
| 异常 | 空工程号、坐标不足 3 个、坐标非数字、工程号重复（不区分大小写，与核心一致）→ 记 error |
| 统计 | 总行数 / 有效 / 异常 / 重复 / 跳过（注释、空行、元数据行） |
| 大文件 | 全量解析，预览只显示前 200 行，超过 2 万行给一条提示 |

### 3.3 与核心脚本的兼容性（关键设计）

解析器会判断这份文件核心脚本能不能直接吃：

* 能（UTF-8 + 逗号 + `工程号,,E,N,R` + 无表头 + 坐标位置一致）→ 直接把**原文件**交给生成；
* 不能（GBK、制表符、空格分隔、带表头、4 列无空列…）→ 在
  `%TEMP%\sm_txt_import\` 写一份 **5 列 UTF-8 规范化副本**给生成用，
  **原文件一个字节都不改**，卡片上明确写"已生成规范化副本（原文件未改动）"。

坐标写副本时沿用**原始单元格文本**（不做四舍五入），避免 `470163.884` 变成 `470163.8839999`。

## 四、平台 / 日期识别规则

### 4.1 优先级

| 优先级 | 来源 | 示例 | 界面标注 |
|---|---|---|---|
| 1 | 文件内明确标注 | `平台：3940`、`炮区日期：1008`、`台阶高度：12` | 文件内标注 |
| 1 | 炮孔编号内嵌 | `BS-3940-0915-P1` → 3940 / 0915（取前 30 条多数票） | 炮孔编号 |
| 2 | 文件名 | `BS-3940-0915-P1-P90.txt`、`3940平台 1008.txt`、`3570取样1023.txt` | 文件名 |
| 3 | 都没有 | 保留页面原值，卡片显示"未识别"，提示手工填 | 未识别 |

### 4.2 明确不做的两件事

* **不从 Z 高程推断平台**：文件里 Z=3960 但编号是 3940 时，平台仍是 3940（测试用例覆盖）；
* **不自动填当天日期**：识别不到日期就留空并提示，绝不用 `today()` 兜底。

### 4.3 日期规范化

| 原始写法 | 结果 | 说明 |
|---|---|---|
| `1008` / `0915` | 原样 | 项目里的炮区编号（MMDD） |
| `2026-10-08` / `2026/10/8` | `1008` | 折算后卡片标注"原写法 2026-10-08 → 1008" |
| `10-08` / `10月8日` | `1008` | 同上 |
| 其它 | 留空 | 不猜 |

### 4.4 冲突处理

* 文件内与文件名不一致 → 采用文件内，卡片与日志给出"平台存在冲突：文件内 3940，文件名 3960"；
* 与页面已有值不一致 → **不覆盖**，保留页面值，卡片列"参数冲突"并给「采用识别值」按钮；
* 页面上的值如果是**上一次导入自动填的**（用 `textEdited` 区分人工编辑），下一次导入可以正常替换，
  不会被误判成"人工修改"。

```
[文件图标] NS-3970-0718-P1-P90.txt   4.5 KB · UTF-8 · 逗号（工程号,,E,N,R）      [已就绪]
 平台 3970            日期 0718            台阶 —

```

* 解析成功：自动跳转本页、`坐标 TXT` 自动填好、平台/日期/台阶填好、预览表直接列出炮孔；
* 有 error（坏坐标、重复编号、空工程号）：仍进入本页，但 **「生成 .xls / .mdb」被禁用**，

* 没有导入任务时卡片是空状态，提供「选择 TXT 文件」（走同一条解析链路）；
* 手工在 `坐标 TXT` 里改了路径 → 导入卡片自动收起（旧任务不再对应当前文件），
  手工流程（浏览、解析预览、生成）完全不受影响；
* 切到别的页面再回来，任务仍在（`AppContext.txt_import`）。

## 九、已知限制

1. 品位表仍需人工粘贴（坐标 TXT 里没有品位数据，这是原始业务流程）；
2. 规范化副本放在系统临时目录，重启后可能被系统清理，但每次导入都会重新生成；
3. 工程号判重不区分大小写（与核心 `parse_txt` 一致），大小写不同的同一孔号会被判重复；
4. 只接收本地磁盘文件（不支持网络路径/压缩包内的 TXT）。
