# 后续改进实施路线图

> 原则：先建立基线、再双轨试验；先保证计算可靠、再提升自动化。不重写、不删除、不覆盖生产算法。
> 所有新算法放独立模块（`data/` `quality/` `spatial/` `boundaries/` `blocks/` `calculations/` `evaluation/` `pipeline_v2/`），与 legacy 双轨对比后经批准才切换。

## 阶段总览与依赖关系

```
阶段A 数据层+质量层（地基） ──→ 阶段B 独立实验算法（双轨） ──→ 阶段C 计算口径对账 ──→ 阶段D 地质约束+综合图可靠性
                                        │                                    │
                                        └──────────── 阶段E 验证体系 ──────────┘
                                                              │
                                                       阶段F 生产化+发布
                                                       阶段G 2.5D/3D（单独立项）
```

- 阶段 A、B 可部分并行；阶段 C 依赖 A（有干净数据才谈对账）；阶段 D 依赖 A/B 稳定；阶段 E 依赖 B/C 有可比较对象；阶段 F 依赖 E 通过。

---

## 阶段 A：数据模型与质量检查（P0，前置）

- **目标**：异常数据不被静默吞掉；数据可定位、可追溯。
- **当前基础**：`oreblocks.load_holes_xls` 能读但无校验；`make_database.py` 已有部分生成逻辑。
- **要解决的问题**：D1（重复工程号/缺失品位/多段化验/异常坐标孔深）。
- **开发任务**：
  1. 新增 `data/models.py`：`Hole`、`SampleInterval`、`Bench`/`Blast`、`GeologyFeature` 数据对象。
  2. 新增 `quality/check.py`：字段完整性、工程号重复、缺失品位 vs 真实低品位、多段化验汇总、重复/近重复坐标、异常孔深、空间离群。
  3. 新增 `quality/report.py`：导入质量报告（文件/工作表/行/工程号定位 + 阻断/警告分级）。
  4. `data/readers.py`：表头识别 + 字段映射的 Excel 读取适配器（保留原 `load_holes_xls` 作为兼容入口）。
- **涉及文件**：新增 `core/data/`、`core/quality/`；`oreblocks.load_holes_xls` 仅加调用不改口径。
- **实现方法**：只读新模块；`load_holes_xls` 结果进新 `quality` 校验器，异常列表返回但不改原数据。
- **前置条件**：确认「多段化验汇总规则」「坐标范围/单位」「废孔容重口径」由地质负责人拍板。
- **测试**：构造含重复/缺失/多段/异常样本，断言每个异常可定位、可阻断。
- **验收**：G1 输入质量闸门 —— 关键异常不静默通过、原始数据保留、错误可定位到行/工程号。
- **交付**：数据字典、校验规则、异常样本集、质量报告模块 + 测试。
- **人工审查**：需要（多段样汇总、坐标单位、废孔口径）。

## 阶段 B：独立算法实验 + 双轨对比（P0）

- **目标**：在不动 legacy 的前提下，产出可横向比较的候选矿界。
- **当前基础**：`strip.zone_outline`（PCA 条带）、`strip._alpha_shape`、`strip.isolated_ring`、Voronoi 已可用。
- **要解决的问题**：D4（固定半径分组、PCA 条带适应性）、D6（自动修补/合并掩盖错误）。
- **开发任务**：
  1. 新增 `spatial/local_scale.py`：k 近邻距离、局部密度、局部邻接图。
  2. 新增 `spatial/cluster.py`：DBSCAN 基线 + HDBSCAN 可选实验（不替换生产判断）。
  3. 新增 `boundaries/base.py`：统一候选边界接口（输入点集→输出多边形+指标）。
  4. 新增 `boundaries/candidates.py`：PCA 外推、Alpha Shape、Concave Hull、Voronoi、各向异性外推 五种候选。
  5. 新增 `evaluation/metrics.py`：有效性、面积、周长、紧凑度、矿孔覆盖、环外孔、碎片数、修补面积、外推尺度。
  6. 新增 `pipeline_v2/run.py`：同炮区跑 legacy_v1 与 candidate_v2，输出对比报告。
- **实现方法**：候选选择用「生产可得的客观信息 + 硬约束/软评分」，**不用独立测试图 IoU 做在线选模**。
- **前置条件**：阶段 A 的数据模型可用。
- **测试**：覆盖条带/弯曲/多分支/孤立簇/稀疏孔五类形态。
- **验收**：G2 几何安全 —— 输出几何有效，多部件/洞/修补/断口连接显式记录，不静默丢矿孔。
- **交付**：`spatial/`、`boundaries/`、`evaluation/`、`pipeline_v2/` + 候选对比报告 + 敏感性报告。
- **人工审查**：需要（连通/分簇是否符合地质）。

## 阶段 C：计算口径对账（P0，依赖 A）

- **目标**：统一并验证面积/体积/重量/平均品位/金属量口径，与 3DMine 单元级对账。
- **当前基础**：口径已在 5 张人工图标定（口径记录 A 节），但存在**多分支**（`oreblocks.Block.compute` vs `strip.average_blocks` 含废孔分支）。
- **要解决的问题**：D2（`round()` 取整可能银行家舍入、容重/废孔/加权口径未与 3DMine 单元级核对、多分支不一致）。
- **开发任务**：
  1. 新增 `calculations/spec.py`：把「单元体积 V_i=A_i×H_i、矿块体积=ΣV_i、重量=Σ(V_i×ρ_i)、孔长加权品位、金属量」写成**唯一**口径文档+函数。
  2. 梳理并登记现有各分支（`Block.compute`、`average_blocks` 含废孔分支、`auto_blocks`），标注各自口径差异。
  3. 新增 `calculations/reconcile.py`：读 3DMine 单元导出（.3dm/.3ds）逐块对账面积/体积/重量/品位/金属量。
  4. 修正 `grade_lenght` 的舍入规则（`int(round())` 与 3DMine「四舍五入」是否一致，逐例核对）。
- **实现方法**：两套候选公式并行计算；只有经负责人批准的口径进生产。
- **前置条件**：3DMine 单元级导出样本（至少含废孔、不同品位、边界单元明显的炮区）。
- **测试**：逐块 + 合计对账表。
- **验收**：G3 计算一致 —— 单位/公式已确认，报告/图件/3DS 逐块一致。
- **交付**：口径确认书、逐块对账表、单位与公式说明。
- **人工审查**：需要（3DMine 口径签字确认）。

## 阶段 D：地质约束与综合图可靠性（P1，可与 B 并行）

- **目标**：错误历史轮廓不进入算法；地质约束可追溯。
- **当前基础**：`composite.py` 双通道扫描 + 缓存。
- **要解决的问题**：D3（开口线自动闭合、3D Polyline 丢 Z、图层黑名单）。
- **开发任务**：
  1. `composite.py` 增强：闭合性检查（开口线不自动闭合，标记待人工）、3D Polyline 顶点 Z 校验、图层白名单 + 人工预览。
  2. 新增 `geology/feature.py`：地质界线/岩性/断层/蚀变数据接口与硬/软约束语义。
  3. 缓存校验改「源文件指纹」而非仅 mtime。
- **前置条件**：地质界线数据规范（坐标/编码/线型语义）。
- **测试**：2D/3D Polyline、闭合/未闭合、图层白名单、缓存有效性。
- **验收**：COM 与 accoreconsole 扫描一致；错误轮廓不进入算法。
- **人工审查**：需要。

## 阶段 E：验证体系与生产切换评估（P0）

- **目标**：证明泛化，防数据泄漏，量化人工工作量。
- **开发任务**：
  1. 新增 `_probe/datasets/`：按**炮区**（非单孔）分训练/标定/验证/独立测试四类，记录每次使用。
  2. 新增 `_probe/benchmarks/`：固定基准 + 新旧双轨对比报告。
  3. 扩展 `evaluation/metrics.py`：除 IoU 外，增加面积/体积/品位/金属量偏差、矿孔覆盖率、废石混入/贫化、块数/碎片、边界修复面积、参数敏感性、人工修正率/耗时（指标定义见附录 C）。
  4. 建立质量评分与低可信复核闸门。
- **验收**：G4 独立测试（未参与调参炮区）+ G5 生产切换（双轨+盲审+回滚）。
- **人工审查**：需要（地质盲审）。

## 阶段 F：生产化、文档、发布（P1）

- **开发任务**：接入正式入口；run_id/参数快照/输入指纹/版本绑定；结构化日志；成果完整性检查；发布包 + 运维手册。
- **验收**：旧版可回退、生产文件安全、按钮对应真实能力、发布版与验收报告一致。

## 阶段 G：2.5D/三维（P2，单独立项）

- 测斜孔迹 + 多台阶 → 2.5D/多台阶原型 → 三维 Voronoi/实体/体积。二维通过 G5 后再启动。

## 关键风险

| 风险 | 等级 | 控制 |
|---|---|---|
| 缺少 3DMine 单元导出/独立炮区样本 | 高 | 先收集资料再启动阶段 C/E，不降标准赶工 |
| 参数过拟合历史炮区 | 高 | 旧配置标为历史标定，独立测试，限制新增特判 |
| 自动修补掩盖边界错误 | 高 | 记录修补前后面积/拓扑/归属，超阈值进人工审核 |
| 综合图误识别 | 高 | 白名单+预览+指纹缓存+双通道对账 |
| 新依赖导致部署失败 | 中 | 隔离环境、固定依赖、目标机复测 |
| 版本/文档不同步 | 中 | 发布绑定 commit+参数哈希+报告 |
