# T03 数据适配与标准化 开发设计方案

> 状态：设计稿，**待确认后实施**。本阶段只做设计，不写代码、不改生产算法。
> 目标：把不同格式、不同来源的炮孔/测斜/化验数据，统一转换为后续算法可直接调用的标准 `Dataset`。

---

## 1. 设计目标与边界

- **输入**：多种 Excel（不同表头/列序）、未来可扩展 SQLite/CSV 等来源的炮孔定位、测斜、化验数据。
- **输出**：一个「标准 `Dataset`」——字段语义明确、单位标准化、可追溯、按平台/日期隔离，且能无损转回 `oreblocks.Hole`。
- **边界**：只做「数据适配与标准化」，**不做**任何算量/圈矿算法改动，**不写回**源文件，**不删除**任何记录。

## 2. 目标数据模型（在 T01 基础上增量）

```
Dataset
├── meta: {source, fmt, coord_sys, length_unit, grade_unit, platform, date, fingerprint}
├── loc_rows:      list[HoleRecord]
│     HoleRecord: hid, x, y, z, depth, trajectory, row, raw, intervals, survey
│                 (新增 trajectory 轨迹类型；survey 关联测斜)
├── intervals:     list[SampleInterval]
│     SampleInterval: hid, frm, to, grade, grade_raw, row   (新增单位由 meta.grade_unit 承担)
├── survey_rows:   list[SurveyRow]
└── issues:        list[Issue]
```

语义显式化（对应验收 §4-4/4-5 缺口）：
- 坐标：`x/y`=E/N（投影坐标），`z`=高程 R，单位米；坐标系记入 `meta.coord_sys`。
- 品位：单位 `meta.grade_unit`（默认 `g/t`）。
- 孔深/区间：单位米，`frm<=to` 且 `to<=depth` 校验。

## 4. 模块接口设计

### 4.1 `adapters.py` —— 统一入口

```python
def load(source, fmt: str | None = None, schema: str | None = None,
         coord_sys: str | None = None) -> Dataset:
    """按来源分派到对应适配器，返回标准 Dataset。
    fmt 省略时按扩展名/内容嗅探；schema 指定字段映射模板名。"""
```

分派规则：`.xls/.xlsx → _load_excel`（复用 readers）；`.db/.sqlite → _load_sqlite`；`.csv/.tsv → _load_csv`。

### 4.2 `schemas.py` —— 字段映射配置化

```python
# 默认同义词表（从 readers 迁出，作为可覆盖的默认 schema）
DEFAULT_SCHEMA = {
    "loc":     {"hid": [...], "x": [...], "y": [...], "z": [...], "depth": [...], "trajectory": [...]},
    "blast":   {"hid": [...], "frm": [...], "to": [...], "grade": [...]},
    "survey":  {"hid": [...], "depth": [...], "azimuth": [...], "dip": [...]},
}

def resolve(header_row: list, sheet_kind: str, schema: dict | None = None) -> dict[str, int]:
    """表头行 → {字段名: 列索引}；未命中的字段返回空，交给 lineage 记录。"""
```

支持：自定义 schema（新增来源/异名表头无需改代码）；表头行搜索窗口可配（默认前 5 行 → 可配 `header_search_rows`）。

### 4.3 `units.py` —— 单位/坐标标准化

```python
def normalize(ds: Dataset, cfg: UnitConfig) -> Dataset:
    """把来源单位换算成标准单位（长度→m，品位→g/t），并写入 meta.coord_sys/units。"""
```

- 长度换算：若来源为 `dm`/`cm`，按配置换算为 m。
- 品位换算：若来源为 `%`，换算为 g/t（需确认换算系数，A 类）。
- 坐标系：仅记录不重投影（重投影属后续 3D 阶段），但做范围 sanity check。

### 4.4 `lineage.py` —— 数据血缘

```python
def trace(ds: Dataset) -> list[dict]:
    """每个标准字段 ← 来源文件(指纹)/工作表/列头/行号，形成血缘表。"""
```

- 记录输入文件 md5 指纹、每字段的映射来源、未匹配列的落点。
- 无法匹配的列/记录 → 输出到 `issues`（`unmapped_column` / `unmatched_record`），不静默丢弃。

### 4.5 关联规则（工程号/样品号/炮孔号）

- **工程号**：跨表主键（定位表 / pit_blast / 测斜表）。
- **样品号**：化验记录级标识，若存在则保留（未来多段化验按样品号对齐）。
- **炮孔号**：空间定位标识；工程号↔炮孔号映射需来源明确（默认工程号即炮孔号，可配映射表）。
- 未匹配：定位表有、化验无 → `missing_grade`（沿用）；化验有、定位无 → `orphan_interval`（沿用）；测斜有、定位无 → `orphan_survey`（新增）。

## 5. 数据流

```
原始文件(.xls/.xlsx/.db/.csv)
   │  adapters.load() 分派
   ▼
源行(row) ── schemas.resolve() 字段映射 ──► 原始 Dataset(raw + 定位)
   │  units.normalize() 单位/坐标标准化
   ▼
标准 Dataset ── lineage.trace() 血缘标注 ──► 标准 Dataset(可追溯)
   │  quality.check()（T02 复用，扩展区间/NaN/测斜校验）
   ▼
标准 Dataset ──► 算法直接调用  /  to_legacy_holes() 兼容 oreblocks
```

## 6. 与现有 `oreblocks` 的兼容

- `to_legacy_holes()` 继续作为「标准 Dataset → oreblocks.Hole」的唯一转换点，保证算量链路零改动。
- 新增等价测试：任一来源样本，经 `adapters.load` → `to_legacy_holes` 后，与 `oreblocks.load_holes_xls` 结果逐孔一致。
- 生产链路不 import `core/data`，互不干扰。

## 8. 验收标准

1. **G1 输入质量**：关键异常不静默通过；缺失/重复/冲突可定位到文件/表/行/工程号。
2. **单位语义**：标准 `Dataset` 的坐标/孔深/品位单位在 `meta` 显式声明，换算有依据。
3. **追溯**：任一标准字段可回溯血缘；未匹配数据有可见提示。
4. **隔离**：不同平台/日期数据通过 `meta.platform/date` 隔离，不串数据。
5. **兼容**：等价测试逐孔一致；生产链路零回归。
6. **只读安全**：源文件指纹（md5）在加载前后一致。
