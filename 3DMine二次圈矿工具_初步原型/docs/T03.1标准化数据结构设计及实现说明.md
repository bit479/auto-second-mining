# T03.1 标准化数据结构 设计及实现说明

> 阶段：T03.1 ｜ 日期：2026-11-06
> 范围：统一标准化数据结构（元数据 / 追溯 / 字段映射 / 多段化验 / 兼容），**不涉及**插值、圈矿、多段合并、删孔、单位换算、生产算量改动。

---

## 1. 实现内容

### 1.1 数据元数据 `DatasetMeta`（`core/data/models.py`）

| 字段 | 含义 | 未知时 |
|---|---|---|
| `source` | 来源类型 excel/sqlite | — |
| `source_file` | 原始文件/数据库路径 | 空 |
| `coord_sys` | 坐标系标识 | `UNKNOWN` |
| `coord_unit` / `elev_unit` / `depth_unit` | 坐标/高程/孔深单位 | `UNKNOWN` |
| `grade_unit` | Au 品位单位 | `UNKNOWN`（不擅自认定 g/t） |
| `platform` / `date` | 数据集所属平台与炮区日期 | 空（可后补） |
| `mapping_name` | 使用的字段映射配置名 | `default` |
| `unit_rules` | 实际应用的单位换算规则 | `[]`（本阶段不换算） |

未知字段一律 `UNKNOWN`，**不允许静默猜测**。

### 1.2 原始数据追溯（`models.py` 记录级字段）

- 每条 `HoleRecord` / `SampleInterval` / `SurveyRow` 新增 `sheet`（来源工作表）+ `raw`（原始列头 → 原始值）。
- `Dataset.field_map` 记录 `{工作表: {字段: 列索引}}`，可回溯「字段映射配置」。
- 追溯链：`source_file → sheet → row → raw(原始字段/值) → field_map(映射) → unit_rules(换算)`。

### 1.3 字段映射配置（`core/data/schemas.py`）

- `DEFAULT_SCHEMAS`：当前确认过的表头写法（含新增 `trajectory`）。
- `resolve_mapping(header_row, kind, schema)`：**精确匹配**（归一化后比对），不做模糊匹配；返回未识别列头清单。
- `register_schema(kind, mapping)`：内存注册扩展；`read_holes/load` 支持 `schema` 覆盖参数。
- 无法识别的列头 → 输出 `unmapped_column`（info）提示，允许后续人工配置，**不静默丢弃、不强行匹配**。

### 1.4 多段化验

- `SampleInterval` 列表**完整保留**同一工程号的全部化验区间，**不提前合并**。
- `last` 规则仅存在于 `to_legacy_holes` 的**兼容选项**，docstring 已明示「不代表已获批准」。

### 1.5 多来源入口（`core/data/adapters.py`，最小实现）

- `load(source, fmt=None, platform="", date="", schema=None)`：按扩展名分派 Excel / SQLite。
- SQLite 约定：库内存在「定位表 / pit_blast / 测斜表」三表，列名与 Excel 表头一致，复用同一套 `schemas` 映射与 `_parse_workbook`。
- 未做 CSV 等其它来源（遵守「不一次性引入大量未验证适配功能」）。

### 1.6 兼容性

- `to_legacy_holes()` 保留，作为「标准 Dataset → oreblocks.Hole」唯一转换点。
- 生产链路（oreblocks/pipeline/strip/deliver/params/grades/composite）**未 import** 新模块、**未改动**。

## 2. 数据流

```
源文件(.xls/.xlsx/.db)
  └─ load() 分派（excel/sqlite）
       └─ _parse_workbook：schemas.resolve_mapping 字段映射（+unmapped 提示）
            └─ Dataset（loc_rows/intervals/survey_rows + meta + field_map + issues）
                 ├─ quality.check()（T02/T02.1 校验）
                 └─ to_legacy_holes()（兼容 oreblocks）
```

## 5. 与原生产链路的兼容性结论

**完全兼容，零回归。** 新模块为独立包，生产链路未引用、未改动；`to_legacy_holes` 保证标准结构可无损回填旧结构；真实 1008 逐孔坐标/孔深与 `oreblocks.load_holes_xls` 一致；全程只读（源文件 md5 前后一致）。
