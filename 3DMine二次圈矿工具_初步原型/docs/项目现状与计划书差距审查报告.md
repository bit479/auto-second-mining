- 两个 GUI（旧 Tkinter / 新 PySide6）都通过**子进程**调 `core/run_strip.py`，命令行参数保持一致；UI 不承载算法 —— 这一点与计划书 §4「UI 不承载算法逻辑」**已经一致**。
- 生产链路：`run_strip.py → pipeline.run_blast → strip.zone_outline + strip.average_blocks → deliver.*`。
- 数据读取：`oreblocks.load_holes_xls`（xlrd），另有 `oreblocks.read_3dm/read_3ds` 读 3DMine 导出单元。

## 4. 核心算法说明（现状）

### 4.1 矿化孔分组 —— `pipeline.pick_zone`

- 先按品位 `>= cutoff` 过滤矿孔；按 `gap=1m` 去重；再按 `adjacent_max=zone_link_m=15m` 的**固定半径**做链式连通分组；取**最大组**为主矿化带，其余为孤立组（`isolated_min_holes` 以上单独圈、以下列待取样）。
- **评价**：单一固定半径，无局部孔距/密度感知；主矿化带 = 最大连通组这一假设在「多矿化带」场景可能错判（计划 P02 已点出）。

### 4.2 外围矿界 —— `strip.zone_outline`

- PCA 求走向 → 中线分左右链 → 内部孔剔除 → 逐段法向外推 `extrude_m` → 两端与无品位孔取中点闭合 → 南端接综合图历史块 → `connect_ring_parts` 自动修补断口。
- Alpha Shape 仅当 `ring_alpha_k>0` 时并入（仅 1004 等个别炮区开）。
- **评价**：这是「PCA 条带 + 外推」模型（计划 P03），对弯曲/多分支/不规则矿化适应性有限，靠 `ring_alpha_k`、`cluster_strip_mode`、`chain_left/right` 等人工参数兜底。

### 4.3 分块定档 —— `strip.average_blocks`

- 每孔 Voronoi 单元裁剪到矿界 → 同档且相接并组 → 面积 `<min_fragment_m2`(40m²) 并入平均品位最近的邻组 → 可选 `merge_gap`/`same_block` 合并 → 每块按整块平均品位定档。
- **评价**：碎片合并只按面积+平均品位差（计划 P05），未考虑公共边长、最小采宽、贫化、采装可行性；块内可能含废孔单元。

### 4.4 品位分级 —— `core/grades.py`

- 唯一来源 `excel_tools/config/grade_profiles.json`，支持金斗山（4 档）/中心矿段（3 档），左闭右开，`ore_cutoff` 工业品位下限。**此项在 v1.13/v1.14 已实现，质量较高**。

## 6. 测试现状与可靠性

| 3DMine 单元级对账 | **无**（仅对照人工图/报告数值） | 待补 |
