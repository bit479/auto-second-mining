## 二、图标异常根因分析

### 2.1 直接原因：DPR 二次缩放导致「只画左上角」

v1.15 的渲染代码：

```python
px = QPixmap(size * dpr, size * dpr)
px.setDevicePixelRatio(dpr)          # ← ① 先告诉 Qt「这张图是 2 倍图」
painter = QPainter(px)               # ← ② 画笔坐标系因此被缩放 1/dpr
renderer.render(painter, QRectF(0, 0, size * dpr, size * dpr))
                                     # ← ③ 又按「设备像素」铺满，等于再放大 dpr 倍
```

Qt 在 `QPainter` 开始时就会按 pixmap 的 `devicePixelRatio` 缩放画笔坐标系。
于是 24×24 的图形被放大 `dpr` 倍后塞进同一张画布，**只有左上角 1/dpr² 的区域落在画布内**。
在 125% 缩放下 `dpr=2.0`（旧代码写死 2.0），实际只显示 1/4 面积 —— 正是
「文件夹图标只剩一个折角」「target 只剩半圈圆弧」「播放键只剩一个三角尖」的成因。

修复：

```python
px = QPixmap(side, side)             # side = round(size * dpr)
painter = QPainter(px)               # 此时 pixmap 还没有 DPR，坐标系 = 设备像素
renderer.render(painter, QRectF(0, 0, side, side))   # 铺满整张画布
painter.end()
px.setDevicePixelRatio(dpr)          # ← 绘制完成后再设，逻辑尺寸 = size
```

同时 `icon()` 会为 1 / 1.25 / 1.5 / 1.75 / 2 / 2.5 / 3 七档 DPR 各缓存一张位图，
`QIcon` 按目标 DPI 精确命中，Windows 125% / 150% 下不再做非整数重采样，边缘不再发虚。

### 2.2 加剧问题的四个次要原因

| 原因 | 表现 | 处理 |
|---|---|---|
| 导航 `iconSize=17` + `border-left:3px` | 图标偏小、选中时整行位移 | 20px 图标；状态条常驻 3px 占位 |
| `QLabel` 承载图标但未设固定尺寸 | 被同行文字挤压，图标只剩一条缝 | 统一 `icons.label()`：`setFixedSize(size,size)` |
| 按钮文本用 `"  " + text` 手工缩进 | 图标与文字基线不一致，长文本时挤压图标 | 去掉手工空格，改由 `padding` + `iconSize` 控制 |
| 24px 网格图画得过密（如 4 个 7×7 方块） | 降到 16–20px 后笔画粘连成"色块" | 重绘图标：减少细节、1.75 描边、小尺寸专用造型（layers 改两层、spreadsheet 减列） |

### 2.3 图标规范（已固化进 `icons.py`）

* viewBox 固定 24×24，`stroke-width: 1.75`，`linecap/linejoin: round`，`fill: none`；
* 尺寸：导航 20px、按钮 16px、功能卡 22px、空状态 34px、窗口控件自绘 10px 线条；
* 全部内联 SVG，无外部图片、无运行时网络请求；
* 颜色由调用方传入，深底用 `#A6BCCF`（hover `#DCE8F3` / 选中 `#DFF0FB`），浅底用 `TEXT_MUTED`；
* 新增图标只允许写进 `icons._SVG`，禁止 Unicode 字符与 emoji 充当功能图标。

## 四、沉浸式标题栏实现

```
┌────────────────────────────────────────────────────────────────────────────┐
│ [镐头] 二次圈矿智能工作台 │ 工作空间 › 单炮区二次圈矿 │ 项目 平台 矿段 ● 状态 ⚙ ─ □ ✕ │
│        MINING WORKSPACE                                                     │
└────────────────────────────────────────────────────────────────────────────┘
```

* 窗口 `Qt.FramelessWindowHint`，但**不牺牲原生行为**：
  * `WM_NCHITTEST` → 标题栏空白区返回 `HTCAPTION`（拖动 / 双击最大化 / 拖边贴靠由系统处理）；
  * 最大化按钮区域返回 `HTMAXBUTTON` → **Win11 Snap Layout** 悬停浮层正常弹出；
  * 四边 6px 返回 `HTLEFT/HTRIGHT/HTTOP/…` → 原生缩放；
  * `WM_GETMINMAXINFO` 把最大化尺寸钉在**工作区**，不遮挡任务栏。
* 窗口按钮自绘（46×56，10px 线条、关闭键 hover `#C42B1C`）；
  由于非客户区收不到 Qt 的 enter/leave，hover 由 90ms 轻量轮询补齐。
* 自检结果（`_probe/ui_selfcheck.py`）：

```
原生命中： 标题栏空白=2 ｜ 最大化按钮=9 ｜ 左边界=10 ｜ 右边界=11 ｜ 内容区=1
最大化几何=1536x864  工作区=1536x864  任务栏让位=是
```

* `WM_NCCALCSIZE` 未拦截、窗口阴影与圆角交由 DWM（Win11 圆角 + 深色边），失败静默降级。
* 非客户区点击 Qt 不会自己处理，因此显式处理 `WM_NCLBUTTONDOWN`（HTMAXBUTTON）与
  `WM_NCLBUTTONDBLCLK`（HTCAPTION）来切换最大化；`_toggle_max()` 带 350ms 去抖，避免双触发。

### 4.1 真实输入验证（`_probe/ui_clicktest.py`、`_probe/ui_dragtest.py`）

用 `SetCursorPos + mouse_event` 发送真实鼠标事件（非脚本调用）：

```
拖动前位置 = (140, 100) ｜ 拖动后位置 = (230, 160) ｜ 可拖动 ✓
双击标题栏后：最大化 = True 尺寸 = (1536, 864)      ← 等于工作区
最大化键第 1 次点击：最大化 = True  尺寸 = (1536, 864)
最大化键第 2 次点击：最大化 = False 尺寸 = (1200, 800)
```

> 注意：`SetCursorPos` 用物理像素，`mapToGlobal` 给的是逻辑像素，两者相差 DPR 倍；
> 测试脚本里已统一换算。窗口几何在分辨率/缩放变化后会被夹回可用区域，不会出现"窗口跑到屏幕外"。

6. 其余 9 个业务页面逐页整改，页头、间距、控件高度、表格列宽全部对齐规范。
7. 底部状态条改为工作区内的 28px 细条，侧栏直通窗口底部。
8. 说明文字对比度提升到 4.5:1 以上。

**工程**

9. 新增 `_probe/ui_selfcheck.py`（布局/图标/截断/原生命中自检）与 `_probe/ui_matrix.py`（截图矩阵）。
10. `app.py` 增加 `--size` / `--scale` 自检参数，便于回归时复现任意分辨率与缩放。
11. 新增 `docs/UI设计规范_v1.16.md`，界面改动有据可依。

**未变更**

12. 圈矿算法、炮孔数据处理、品位分级规则、生产参数、面积/体积/吨位公式：**全部未改**。
13. 旧版 Tkinter 界面保留；所有页面与功能入口均保留。
