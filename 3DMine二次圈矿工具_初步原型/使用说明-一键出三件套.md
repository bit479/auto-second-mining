# 一键出三件套 · 使用说明

## 1. 怎么启动

双击项目根目录的 **`启动二次圈矿工具.bat`**（无控制台窗口），或命令行：

```
C:\Users\Administrator\AppData\Local\Programs\Python\Python313\python.exe -X utf8 client\gui.py
```

## 2. 要给哪两个输入

| 输入 | 说明 |
|---|---|
| ① 炮孔数据库 Excel | 如 `1、3940平台 炮孔数据库1008.xls`（含 定位表 / 测斜表 / pit_blast 品位表） |
| ② 综合图 DWG | 该平台的年度综合图，如 `5、 北部山头3940平台二次圈矿矿块图-2026综合.dwg`。**每次手工指定**（选 Excel 后程序会自动在同目录/上级目录找带"综合"的 dwg，找不到就手工选） |

平台/日期从文件名自动识别（可手改），输出目录默认为 Excel 同级的
`二次圈矿成果_<平台>_<日期>`。

## 3. 产出三件套

| # | 文件 | 说明 |
|---|---|---|
| 1 | `<平台>平台 <日期>炮孔数据报告.xlsx` / `.png` | 分档列块号、体积、重量、平均品位、金属量（百克，3 位小数）+ 炮孔品位统计行；小计按精确值求和后四舍五入 |
| 2 | `<平台>平台 <日期>二次圈矿矿块图_2010.dwg`（失败则留 `.dxf`） | 矿块图：彩色矿块、1 m 方格格心品位、炮孔十字+工程号+品位、矿块号引线（从块中心出发）、**矢量报告表**；DWG 2010 = AC1024 |
| 3 | `<平台>平台 <日期>矿块边界线.3ds` | 每个矿块一条字符串并带名称，格式对齐 3DMine 选择集 |

## 3.1 从坐标 TXT + 品位表生成炮孔数据库

主界面「Excel 工具」下面点 **"从坐标 TXT + 品位表生成 .xls/.mdb…"**，
也可以直接把 `BS-…txt` 拖进主窗口。

1. 坐标 TXT：`BS-3940-0915-P1,,470068.592,4349643.299,3941.101`（工程号,,E,N,R）；
2. 品位表：把 Excel 里那几列直接粘进大文本框（也支持 Markdown 表格）；
3. 平台/日期自动识别；台阶高度默认 **10 m**；
4. 先点 **解析预览** 检查缺孔/多孔/同号冲突；
5. 点 **生成 .xls + .mdb**。

输出：

* `1、<平台>平台 炮孔数据库<日期>.xls`
* `2、<平台>平台炮孔数据库<日期>.mdb`

孔深按整数写库：定位表「最大孔深」、测斜表「深度」、pit_blast「至」三处都四舍五入取整
（9.5→10、8.5→9），坐标 E/N/R 仍保留 3 位小数；`.mdb` 保留
`config/style/constraint` 元数据。目标文件已存在时，先备份到 `bak\` 再覆盖。

## 4. 走的是哪套算法

`core/run_strip.py`（参数已用 0915/0922/1003/1004/1008 五张人工图标定）：

1. 读库 → 分档；矿孔按 **15 m** 连接半径分主矿化带 / 待取样孤立组；
2. 左右链（走向中线方案）+ 局部法向外推 **3 m** → 外围矿界；南端自动接综合图历史块（≤8 m，只并真正接上的那一块）；
3. 品位界限：**通用自动识别**（跨档相邻孔的 Voronoi 分界，不用给孔号）；
4. 分块定档：同档连通块 → **<40 m² 的碎片并入平均品位最接近的邻块** → 按**整块平均品位**定档，体号高档在前；
5. 算量：单元体积＝单元面积×`round(孔深)`；品位＝Σ(长度×孔品位)/Σ长度；容重 0–0.5 档 2.65、其余 2.7；金属量＝重量×品位/100（百克）。

口径细节见同目录 **`口径确认记录.md`**。

## 5. 需要本机 AutoCAD 吗

**只有"转 DWG 2010"这一步需要**（走 AutoCAD COM，只读打开 DXF、另存 2010、随即关闭自己开的那个文档，不动你已打开的图纸）。
如果 AutoCAD 没开或转换失败，程序保留 DXF，在成果图那一栏显示 DXF 路径，你手工在 CAD 里另存 2010 即可。GUI 里可以取消勾选"转 DWG 2010"跳过这一步。

## 6. 批量模式（整个目录一次跑完）

GUI 上点 **"批量跑整个目录…"**，选一个"里面每个子目录放一天炮区"的父目录
（如 `7、单日数据`，子目录里要有 `1、*.xls`），程序会把里面所有单日炮区跑一遍，输出到
`<父目录>\_批量汇总\`：

| 文件 | 内容 |
|---|---|
| `批量汇总.xlsx` | 4 个表：明细（每块一行）、按日合计、参数、**并图状态**（哪几天还没并进综合图，按几何重合度判） |
| `批量汇总.png` | 各炮区体积按品位档堆叠对比（柱顶标体积 + 金属量） |
| `批量总览.png` | 每天一张分块图拼在一起 |

命令行等价写法：

```
python core\run_batch.py "D:\...\7、单日数据" "D:\...\5、…2026综合.dwg" "D:\...\_批量汇总"
```

加 `--full` 会给每天再生成完整三件套（慢）。

## 6.9 一键日流程

GUI 上"一键出三件套"那个按钮，勾上 **"圈完顺手并入综合图副本（出预览）"** 就是完整日流程：

```
选数据库 + 综合图 → 一键 → ① 报告 xlsx/png  ② 成果图 DWG 2010  ③ 边界线 .3ds
                          → ④ 并入综合图副本 + 预览图（原件不动）
```

命令行三步等价：

```
python core\run_strip.py "<数据库.xls>" 3940 <日期> "<输出目录>" "<综合图.dwg>"
python core\dxf2dwg.py "<输出目录>\<…>二次圈矿矿块图.dxf"
python core\merge_to_composite.py "<综合图.dwg>" "<输出目录>\<…>矿块边界线.3ds"
```

想单独查"哪些炮区还没并进综合图"：

```
python core\merge_status.py "D:\...\7、单日数据" "D:\...\5、…2026综合.dwg"
```

## 7. 把当天矿块并进综合图（只改副本）

GUI 上点 **"并入综合图（副本）…"**，选综合图 + 当天的 `…矿块边界线.3ds`，程序会：

1. 把综合图**复制**成 `…-2026综合_并入<日期>.dwg`（**原件一个字都不动**）；
2. 用 AutoCAD 打开这个副本，把 .3ds 里每个矿块加一条**闭合多段线**，放到与品位档同名的图层（`0.500-1.000` / `1.000-1.500` / `1.500-3.000` / `3.000-999.000`，缺图层就新建、颜色跟人工图层一致）；
3. 存盘、关闭副本，日志里告诉你"并入了几块、放在哪层"。

你复核副本没问题后，再自己决定要不要用它替换原件。命令行等价：

```
python core\merge_to_composite.py "<综合图.dwg>" "<…矿块边界线.3ds>"
```

### 7.1 确认替换原件（先自动备份、可回退）

GUI 上点 **"确认替换综合图原件…"**，选那个 `…_并入1008.dwg` 副本，会**弹窗列出将要做的文件操作**，
确认后执行：

1. 原综合图改名备份为 `<原名>_原版_YYYYmmdd_HHMMSS.dwg`（**不删除任何东西**）；
2. 副本**复制**成原综合图的名字（副本本身保留，可反复替换）；
3. 日志给出回退办法：把备份改回原名即可。

命令行等价（`--dry-run` 只演练不改文件）：

```
python core\apply_merge.py "<…_并入1008.dwg>" --dry-run
python core\apply_merge.py "<…_并入1008.dwg>"
```

## 8. 回归脚本（开发用）

### 8.1 一键标定（换一个新炮区时用）

GUI 上点 **"用人工图标定本炮区…"**：选该炮区的人工圈矿图 DWG，程序会自动
① 只读扫描这张图（AutoCAD COM，带重试）→ ② 以"矿界与人工块并集的 IoU"为目标，
贪心搜"哪些孔该进左/右链、外推距离取多少" → ③ 写进 `圈矿参数.json` 的对应炮区。

命令行等价（`--extrude` 可联搜外推距离，`--write` 才落盘）：

```
python core\calibrate.py 1003 "D:\...\5、 北部山头3940平台二次圈矿矿块图1003.dwg" --write
python core\calibrate.py 0922 "D:\...\…0922.dwg" --extrude 6 7 8 9 --write
```

**改动代码前后各跑一次 `_probe\selftest.py`**，全绿再提交（退出码 0 = 达标）：

```
python _probe\selftest.py
```

它会拿 5 张人工图当基准，打印矿界 IoU、块数、体积差，并按达标线判红绿：
1008 IoU≥0.90 且体积 ±5%，其余 IoU≥0.75 且 ±20%（0922 特殊，不纳入）。

## 9. 参数（按平台可覆盖）

参数存在项目根目录 **`圈矿参数.json`**，GUI 参数区可直接改并"存为当前平台"。

| 参数 | 默认 | 依据 |
|---|---|---|
| `extrude_m` 外推距离 | 3.0 m（**1003 单独 2.5 m**） | 量 5 张人工图"块边界到最近矿孔"：1008 2.97 / 0915 2.88 / 1004 2.97 / 1003 2.45 |
| `zone_link_m` 孤立孔连接半径 | 15.0 m | 1004 人工图把间隔 10.6~13.9 m 的孔连成一条；1008 的 P43 离主带 21.4 m 没圈 |
| `min_fragment_m2` 最小块段 | 40 m² | 用 5 张人工图扫参数、按"两孔是否同块"的一致率标定（0.936 最优） |
| `merge_gap_m` 接综合图间距 | 8.0 m | 1008 实测 |
| `ring_alpha_k` 外轮廓兜底 | 0（**1004 单独 1.5**） | 孔列多/走向弯的矿带，链式外推会夹断；并上"矿孔外轮廓+外推"后 1004 体积差 −5.6%→+2.3% |
| `isolated_min_holes` 孤立组最小孔数 | 3 | 孤立小组孔数 ≥ 此值就**单独圈成矿块**（0922 的 4 孔组）；更少的列"缺工程，待取样"（1008 的 P43/P47 是 2 孔组） |
| `chain_left` / `chain_right` 人工指定链 | 空（自动判定） | 某个炮区的自动分链跟人工图不符时，把该孔号写进来强制进左/右链；可用 `_probe\tune_chains.py` 自动标定 |
| `repair_tip_m` 修补廊道端头 | 0.8 m（0915/0922 用 −1 = 自动） | 自检修补时廊道伸出多少；太小会让孔贴着矿界 |
| `grid_res_m` / `simplify_m` / 容重 | 1.0 / 0.8 / 2.65·2.7 | 需求口径 |

## 10. 出问题怎么办（常见故障的中文提示）

> **完整的排查手册在 [故障与排查.md](故障与排查.md)**（症状 → 先看哪儿 → 怎么办，
> 含综合图、出图要素、验收三类的具体命令）。下面是"日志里会看到什么中文提示"的速查表。

跑流程时若出错，日志里会给**明确的中文提示**，不会只丢一串英文异常：

| 情况 | 提示 |
|---|---|
| 数据库路径写错 | `[错误] 找不到炮孔数据库：…` |
| 拿非 Excel 当数据库 | `[错误] 炮孔数据库应当是 .xls/.xlsx，收到的是：…` |
| Excel 打不开/被占用 | `打不开这个 Excel（…）：…` |
| 缺少工作表 | `数据库缺少工作表：定位表/pit_blast。这个文件里现有：…` |
| 坐标/孔深/Au 不是数字 | `定位表第 N 行读不动…` / `pit_blast 第 N 行的 Au 不是数字…` |
| 认不出日期 | `[错误] 认不出日期（炮区号），请…` |
| 一个矿块都没圈出 | `[错误] 没圈出任何矿块…请核对数据库` |
| 综合图没读到历史块 | `[提示] …要么该图没有，要么 AutoCAD 没开且没有扫描缓存`（照常出成果） |
| 成果文件被 Excel/CAD 占用 | `[错误] 有成果文件正被占用…关掉占用它的程序再跑一次即可` |

每次跑完（成功或失败）成果目录里都会留一份 **`运行记录.txt`**：运行时间、耗时、
输入文件、当时生效的全套参数、产生的文件清单、以及完整日志——出问题直接看它。

## 改完东西怎么验收（一条命令）

```
python _probe\accept_all.py            # 缺省跑 3940 + 3960
python _probe\accept_all.py 3940       # 只跑一个平台
```

> 不想记命令就**双击 `跑验收.bat`**（全量，跑完自动打开 `验收报告.md`）；
> 想快一点就双击后在命令行加 `--quick`，即 `跑验收.bat --quick`。

它会依次跑三件事，退出码 0 = 全过：

1. **圈矿验收闸门**（`selftest.py`）——两档：常规档（综合图含当日本身块也照贴，生产跑法）
   和**严格档**（把综合图里与人工图重合的"当日本身块"排掉，模拟新炮区，只报数不设闸门）；
2. **报告口径回归**（`report_check_all.py`）——把生成的报告 xlsx 与人工报告逐项比：
   版式（标题/表头/小计/合计/品位统计行）、**每块口径自洽**（重量=体积×容重、
   金属量=重量×品位÷100、平均品位=金属量÷重量）、合计体积/重量/品位/金属量的偏差；
3. **精确模式自检**——用人工在 3DMine 里画好的四段 .3ds 拼矿界（`outline_files`），
   与人工 1008 图求 IoU（要求 ≥0.90，实测 0.962）。

当前状态（2026-10-14）：3940 五个炮区 IoU 0.62~0.95、体积 −1.3%~+6.1%；
3960 十二个炮区 IoU 0.53~0.93、体积 −2.9%~+6.8%，块数全部与人工图一致；
报告口径回归全过。

## 参数台账（想知道"每个炮区到底改了什么、为什么"就看它）

```
python _probe\params_report.py            # 全部平台
python _probe\params_report.py 3960       # 只看一个平台
```

它按"全局默认 → 平台覆盖 → 炮区覆盖"三层列出来：每项写了什么值、跟上一层比变了多少、
以及当初为什么这么改（参数里的 `_说明`）。两层作用：

* 一眼看出哪些值是**按人工图标定**出来的、哪些是拍的；
* 挑出"覆盖了但没写依据"的炮区（会打 ⚠）——方便补说明，别留暗账。

（2026-10-14 用它清掉了 `params.py` 里 `"1003"`/`"0915"` 这类**只有日期的旧键**：
它们从来不生效（`for_blast` 只认 `"<平台>-<日期>"`），却会被统计脚本当成"一个叫 0915 的平台"。
参数唯一生效来源是 `圈矿参数.json`。）

## 界面上也能自查（2026-10-14 加）

客户端第二排按钮：

| 按钮 | 干什么 |
|---|---|
| 查看参数台账 | 把 `params_report.py` 的输出打到日志区（会按上面填的平台号过滤） |
| 跑一键验收（全量，约 3 分钟） | 跑 `accept_all.py`，日志区逐行显示；跑完右下角给结论 |
| 快检（只挑代表炮区） | 同上，`--quick`：成果图自检只挑代表炮区，约 1 分钟 |
| 打开验收报告 | 打开 `验收报告.md`（带时间、代码版本、逐项结论、完整日志） |

标定时可以加 `--by-volume`：在"块数与人工图一致、IoU 不掉超过 0.02"的候选里，
取体积差最小的那个外推距离（0922 就是靠它从 −18.1% 拉到 −13.1% 的）。

| 脚本 | 用途 |
|---|---|
| `_probe/review_1008.py` | 1008 自动 vs 人工图叠加评审出图 |
| `_probe/compare_manual_auto.py` | 五个炮区"人工图 vs 自动"对照出图 |
| `_probe/review_batch.py` | 五个炮区自动圈矿批量出图 |
| `_probe/tune_blocks.py` | 用人工图标定"最小块段面积 / 碎片并入规则" |
| `_probe/scan_manual_retry.py` | 只读扫描人工 DWG（带重试，AutoCAD 忙时不至于中断） |
