## 数据表结构

炮孔数据库（xls 与 mdb 同构）三张表：

| 表 | 列 |
|---|---|
| 定位表 | 工程号 · 开孔坐标E · 开孔坐标N · 开孔坐标R · 轨迹类型 · 最大孔深 |
| 测斜表 | 工程号 · 深度 · 方位角 · 倾角 |
| pit_blast | 工程号 · 从 · 至 · Au |

* mdb 里还有 `config_table_3dmine` / `style_table_3dmine` / `constraint_table_3dmine` 三张 3DMine 元数据表，**合并时不可改**。
* mdb 的 `pit_blast` 带 `(工程号, 从)` 唯一索引 → 判重必须按两列。
* xls 与 mdb 的数值精度不同（3DMine 导出差异，如最大孔深 11.101 vs 11.0），两套独立维护，不做交叉修正。
* **生成的库**（`core/make_database.py`，v1.12 起）孔深一律整数：定位表`最大孔深`、
  测斜表`深度`、pit_blast`至` 都走 `round_int()`（Decimal ROUND_HALF_UP，**不是** `round()`）；
  坐标 E/N/R 仍 3 位小数。

## 报告格式

单日报告 = 标题行 + 表头(类型/体号/体积/重量/平均品位(Au)/金属量（百克）) + 各品位档明细 + 小计 + 合计，
其后可跟若干"3DMine 炮孔数据库报告"附录。综合总表 = 这些"标题→合计"块从上到下堆叠，块间空 1 行。

* 平均品位 = 金属量 × 100 ÷ 重量（不是算术平均）。
* 老报告用「总计」结尾，新报告用「合计」。

## 报告汇总的两种口径

一份源文件（3DMine 报告，列：类型/体号/体积/重量/平均品位(Au)/金属量）怎么变成"一个矿块"：

| 口径 | 规则 | 用在 |
|---|---|---|
| `total`（**默认**，1011 起） | 取每份文件**第一处「总计」行**整行当矿块；**档位由矿块品位反推**（源档位不可用，一份文件的总计可能跨几个源档位）；档位从高到低、同档内按**文件顺序**；**体号重新编号 1→N** | 1011 及以后 |
| `detail`（旧） | 把每行明细拆开按档归组，体号原样保留 | 0915 / 0922 / 1008 |

* 档位区间：`0.000-0.500` / `0.500-1.000` / `1.000-1.500` / `1.500-3.000` / `3.000-999.000`，**下限含、上限不含**。
* 单矿块档位的小计品位写 `=E<该行>`（四格全引用上面那一行）；多矿块档位写 `=F<小计行>/D<小计行>*100`；
  合计写 `=F<合计行>/D<合计行>*100`。这三条是照人工成果一比一复刻的。
* 附录截到「总计」行为止（总计行下面可能挂着杂项行，不带进去）。

### 报告命名约定

默认标题 / 输出文件名 = `<矿名><平台号>平台<日期>炮孔数据报告`，如 `北部山头3940平台1011炮孔数据报告`。

* 平台标签取路径段里形如 `北部山头3940平台` / `3940平台` 的片段；

* 路径里没矿名就补默认前缀 `北部山头`（`--mine-prefix` 可改）。

### 发版流程（照这个走，别漏）

1. **改版本号**：`3DMine二次圈矿工具_初步原型/client/gui.py` 的 `VERSION = "vX.Y"`
   （窗口标题会显示，是判断"跑的是哪版代码"的依据）。功能新增 → minor（v1.3→v1.4），纯修复 → patch。
2. **同步文档**：`README.md`（Excel 工具章节）、`交付说明.md`、`项目结构说明.md`。
3. **写发版说明**：`_probe/release_notes_v1_4.md`（文件名 = tag 的点换成下划线），
   内容照 v1.3 那份的风格：新增功能 → 表格 → 判重/安全 → 验收数字 → 怎么用。
4. **打包**：`python _probe/build_release_zip.py v1.4` → `release_v1/second-mining-tool-v1.4.zip`。
   排除项在脚本里（`_out`/`归档`/`__pycache__`/`.bak`/`.bmp` 等），**别手工改 zip**。
5. **提交 & 打 tag**：`git tag -a v1.4 -m "…"` + `git push origin main` + `git push origin v1.4`。
6. **发 Release**：用 `python _probe/publish_release.py --tag v1.4`
   （title 走脚本内置映射，没配就走 `<tag> —— 二次圈矿工具`，与 v1.2.1/v1.2.2/v1.3 一致）。
7. **验签**：`gh release download <tag> --pattern "*.zip"` 下载回来比 MD5，再解包跑三套自检。

⚠️ **`gh release create` 在本机会失败**：它创建后要 PATCH 一次
`api.github.com/repos/.../releases/<id>`，这条连接反复被 `wsarecv ... forcibly closed` 掐断，
gh 会把已建的 release 回滚删除，最终报 `release not found`。**改用 `publish_release.py`**
（只发 POST + 传资产到 uploads.github.com，不碰 PATCH）。

### 两个反复踩的坑

1. **`.gitignore` 中间带斜杠的规则会被锚定到仓库根**：`Excel处理工具/_out/daily_test/` 匹配不到
   搬家后的路径；`_out/daily_test/` 也不行（中间有斜杠）。**要写 `**/daily_test/`**。
   而且 gitignore 对**已跟踪**的文件无效，得先 `git rm -r --cached` 撤出索引。
2. **行尾符**：多数文件是 CRLF，但有些是 LF。用 Python 文本模式 `open(p,'w')` 整文件重写会把 LF 变成
   CRLF，造成整文件虚diff（`test_merge.py` 3 行变 145 行、`test_daily_merge.py` 88 行变 480 行，犯过两次）。
   **改文本文件优先用 Edit/Write 工具**；必须用 Python 时加 `newline=''`。

## 损贫计算工具（独立仓库 `bit479/loss-dilution-tool`，本地 `D:/WK/损贫计算工具`）

数据语义上有两条**必须知道**的，否则会算错：

1. **炮孔数据报告里，「合计」行下面的 `3DMine 炮孔数据库报告` 附表是拆分、不是新数据**。
   例：主表 `1.000-1.500 体号1 体积1101.775` → 附表 `1.5-3 374.494` + `1.0-1.5 297.305` + `429.977`，
   附表「总计」= 主表那一行。**解析到「合计/总计/汇总」就停**（「小计」要继续读），
   否则总量虚高约 3%。有的报告还会挂 `炮孔品位统计（孔数）` 两列小表，同样不能当数据行。
2. **日期文件夹里可能再套一层 `二次圈矿成果_xxx\` 导出副本**。扫描必须"这一层有报告就只认这一层"，
   用 `rglob` 会把副本算两遍（日志还写着"已忽略"，最容易骗过人）。

**「本月未出矿量表」（v0.7，`core/unmined.py`）的品位口径与合计表相反，别搞混**：

- 明细行品位 **取报告「平均品位(Au)」原值，不反算**。人工表就是抄原值的（1.547 / 0.825 / 0.61），
  反算成 1.5466467 / 0.82498 会一格都不等。
- 底部「品位范围汇总」的品位**是反算的**（该档金属量 × 100 ÷ 该档矿量，6 位），人工表也这样。
- 输入是**平铺目录**（`10月未出矿量\` 下直接放 `XX平台 MMDD炮孔数据报告.xlsx`），
  不是按日期分子文件夹，所以走独立的 `scan_reports`，不要套 `scan_day_folders`。
- 山头从标题取；标题没写（如「3920平台 1007…」）→ 同平台其它文件投票 → `DEFAULT_REGION` 兜底。
  3920 只属南部，3930/3940 两边都有、默认北部。
- 已用 9 月 3940-0915 与人工《9月未出矿表》7 行逐格核对：**矿量、品位 Σ差 都为 0**；
  金属量 3 条差 0.007~0.010 —— 人工表 32.403/107.528/24.894 vs 现报告 32.396/107.538/24.889，
  是报告后来重导过，不是算错。
- 版式：宋体 11 / 全细边框 / 日期 `m\.d` / 汇总块底色 **E54C5E**（主题 accent6），数据区无底色。

首页（`动用储量汇总`）的公式形态：三块汇总 → 「平台×品位」小表 → 明细，**全用加法**
（用户明确要求，不要 SUMIF）。改这块时记得：引用明细要用报告的 `col_map` 取列，
`/10` 要写 `=(a+b+c)/10`。
（这是 v0.8 之前的 `--layout legacy` 版式，现在默认走人工表 12 页，见下。）

**输出默认是人工表版式**（v0.8 起，`core/report_writer.py`，`RunOptions.layout="manual"`）：
一张《X月金斗山计算表》，12 个业务页签 + 末尾 `待人工审核/完全重复明细/处理日志`。
页签顺序、配色、公式、列宽行高都照 `10月金斗山计算表9.18-10.17.xlsx` 复刻。
改这块务必记住几条容易踩的：

- 汇总表的「**体号」列其实是笔数**，不是矿块编号。

## CAD 合图工具（`D:/WK/CAD合图工具`，2026-10 建）

把每月单日「二次圈矿矿块图.dwg」按原坐标并入地形图，**一天一个图层（块参照法）**，按平台各出一张。
主程序 `merge_dwg.py`：扫描 → 暂存成 B0001.dwg → 生成 GBK 的 .lsp/.scr →
`E:/gzRJ/CAD/AutoCAD 2023\accoreconsole.exe /i 底图副本 /s 脚本` → 原地 QSAVE → 重开自检 → 出 CSV 日志。

四条硬经验：
1. `-INSERT` 会按 **INSUNITS** 自动缩放（源图毫米+目标英寸 → 0.0394）。插入前 `(setvar "INSUNITS" 0)`，
   插入后强制 41/42/43=1、50=0。
2. accoreconsole 的 **脚本路径不能有中文**（报"未找到文件"），且必须先 `(setvar "SECURELOAD" 0)`；
   stdout 是 UTF-16LE 重定向，直接 grep 抓不到。
3. **EXPLODE 碰到 OLE2FRAME 会中断**，别用"炸开再比对"验几何；验块参照的插入点/比例/旋转即可，
   文字比对要用全图唯一串并容忍 1mm 末位差（块内 TEXT 的 (10) 会被重算，真实位置在 (11)）。
4. `-PLOT` 在 accoreconsole 里设备列表为空，出不了 PDF。
5. **OLE 缩小的基点必须用 OLE 自己的 group 10（插入角点），不能用中心**。
   用中心时左上角会向内平移半个宽度（73m 的表缩到 10m → 偏 31m），结果图上看着就是"Excel 图被挪走了"。
   改成 `(setq cx (car p1) cy (cadr p1) cz (caddr p1))` 后，65 个 OLE 逐个回源核对 **0.00m 偏差**。
   另：`entget` 打印坐标是科学计数法（`4.34973e+06`），**看差值会被误导成"高度没缩"**，
