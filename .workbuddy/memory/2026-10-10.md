## 新建「Excel 对比工具」（D:\WK\N CRT\Excel对比工具）

需求：对比两个 Excel 的不同并输出报告。用户选择：逐单元格对比 + Excel 报告(差异高亮) + 新建独立程序
（不复用 Excel处理工具 框架，单独一套，但思路一致）。

### 结构
- `reader.py`：读 xlsx/xlsm（data_only 取公式值）/csv（utf-8-sig→utf-8→gbk 兜底）/xls（需 xlrd，缺失则友好报错）。
  统一结构 {sheet: [[cell,...]]}。
- `compare.py`：逐工作表、逐单元格比对。type: changed/only_a/only_b；数值按容差 1e-9，
  字符串/数字混合也按 float 归一比较；空白(None/空串/纯空格)视为相等。输出 sheets 列表 + totals 统计。
- `writer.py`：写 xlsx 报告，3 类 sheet——
  1) 汇总（文件路径/各表行列数/修改·仅A·仅B·差异合计/总计）
  2) 差异清单（工作表/坐标/类型/A值/B值，类型列颜色标注）
  3) 对比_<表名> 高亮可视化（修改=黄 FFF2CC / 仅A=绿 C6EFCE / 仅B=红 FFC7CE）
- `main.py`：CLI，`python main.py A B [-o out.xlsx]`，无参数启动 GUI。
- `gui.py`：tkinter 界面，选 A/B/输出、开始对比（线程执行防卡）、日志、打开报告。
- `启动对比工具.bat`：纯 ASCII，`for %%X in (pythonw python py python3)` 探测带 tkinter+openpyxl 的 python，
  用 `%~dp0gui.py` 启动（避免中文路径乱码）。

### 验证
- `tests/selftest.py`：造已知差异样例，断言 changed=2/only_a=6/only_b=3、sheet 结构、高亮颜色，全部通过。
- CLI 实跑验证：报告正确，差异清单逐条列出。

### 踩的坑（已修）
**高亮可视化网格最初只从文件A生成**，导致「仅B存在」的单元格（A里没有）根本不出现在网格里、
自然也不高亮。改为取 A、B 两文件**并集**维度，单元格显示 B 的值(无则 A 的值)，再按 mark 上色。
对比单元格时 only_a/only_b 分支不计 `compared`（只在两文件都有的格计入 compared），统计口径一致。

## 修复「启动对比工具.bat 启动不了」（10-10 后续）

### 根因（两次失败，两次不同）
**第一次（选不到 Python）**：原 .bat 只靠 `where` 在 PATH 找 python/pythonw/py/python3。
本机系统 Python `C:\Users\Administrator\AppData\Local\Programs\Python\Python313`
（带 tkinter+openpyxl）**没加进 PATH**；PATH 里第一个 pythonw 反而是托管版
`C:\Users\Administrator\.workbuddy\binaries\python\versions\3.13.12`（**无 tkinter**），
`py` 启动器才指向系统版。→ 改为加「目录探测」分支解决。

**第二次（乱码+一闪崩溃，真正元凶）**：重写后的 .bat 仍含 **153 个中文 UTF-8 字节**
（在 `REM` 注释与 `echo` 提示里）。Windows cmd.exe 按 GBK 解读 .bat，中文字节变乱码，
部分字节恰好撞成 `)` `(` `&` 等特殊符号 → 批处理解析炸掉，报 `此时不应有...`、
`不是内部或外部命令`、大段 GBK 乱码。**这是用户看到的「还是启动不了」的真实原因。**
→ 彻底重写为**零中文**（0 非 ASCII 字节、无 BOM），中文提示改由 Python（UTF-8 安全）弹窗。

### 修复
重写 `启动对比工具.bat`：
1. 先试 PATH（pythonw/python/py），import tkinter+openpyxl 成功才用；
2. PATH 里没有就**直接探测安装目录**：`%LOCALAPPDATA%\Programs\Python\Python3xx`、
   `C:\Program Files\Python3xx`、`C:\Python3xx` —— 不依赖 PATH；
3. 顶部 `cd /d "%~dp0"` 保证相对路径正确；
4. 优先 `pythonw`（无控制台），无则用 `py`/`python`。
`gui.py` 入口加顶层 try/except 兜底：pythonw 静默崩溃改为弹窗 + 写 `gui_error.log`。

### 第三次失败：`-dp0gui.py` 找不到（start 空标题陷阱）
用户双击报 `windows 找不到文件 ‘-dp0gui.py’`。根因：`start "" "%PYW%" ... "%~dp0gui.py"`
用**空标题 `""`**，若 `%PYW%` 为空，整行变成 `start "" "" -X utf8 "%~dp0gui.py"`，
`start` 把最后一个引号串 `%~dp0gui.py` 当成「要打开的文件名」→ 报找不到。

`GUISCRIPT=%~dp0gui.py`，不存在则回退相对名 `gui.py`（顶部已 `cd /d "%~dp0"` 切到 bat 目录）。
实测 `start "ExcelDiff" "exe" args` 形式 rc=0 正常、且 `%~dp0` 在 start 参数里能正确展开。
**通用规则**：写 `.bat` 拉 GUI 时，`start` 第一个引号参数务必给**非空标题**，避免空标题歧义。

## 修复「窗口一闪即逝（pythonw 真崩）」（10-10 后续）

用户反馈：改完 .bat 后能选到 Python，但窗口弹出后立刻消失、客户端不启动。——这是
`mainloop()` 运行期 **C 级崩溃**（WER 弹窗一闪），不是启动失败。pythonw 丢 stderr，原
`__main__` 的 try 抓不到 mainloop 内回调异常，所以静默。

### 真正根因（dragdrop.py 子类化窗口过程）
`orig_proc = WNDPROC(orig)` 直接把 `GetWindowLongPtrW` 返回的 `c_void_p` 当函数指针。
64 位下 `WNDPROC(c_void_p)` 可能得到**被截断/错误的地址**，真实桌面消息流调用原始窗口
过程时 → 访问违规 → 进程崩（窗口一闪消失）。headless 环境收不到真实 WM_PAINT 等消息，
所以 agent 里 `pythonw gui.py` 能存活 6s 无法复现，极具迷惑性。

### 修复
1. `dragdrop.py`：`orig_proc = WNDPROC(int(orig))` —— 用 `int()` 取完整 64 位地址再转函数
   指针（子类化标准做法）。并修重入：WM_DROPFILES 回调改 `root.after(0, ...)` 派发到主线程，
   绝不在 wndproc 里同步调用 tkinter（`var.set`/`update_idletasks`）。
2. `gui.py`：绝不静默兜底——`root.report_callback_exception` 写日志；`root.mainloop()` 包
   try/except；顶层异常用 **ctypes MessageBoxW** 原生弹窗（点确定前不消失）+ 写 `gui_error.log`；
   每次启动先清空日志，记录 set_app_user_model_id→Tk→App→set_window_icon→enable_drop→mainloop 各步。
3. 新增 `启动对比工具_调试.bat`：用控制台 python 跑，崩溃时直接显示红色 traceback。

### 验证
- `pythonw gui.py` 6s 存活，gui_error.log 各步全 OK、无 stderr ✅
- 直接调用 `orig_proc(hwnd, WM_PAINT/WM_ERASEBKGND, ...)` 返回 0 不崩 ✅（证明子类化原始过程地址有效）
- 关键坑：`SetWindowLongPtrW` 子类化时，原始过程必须用 `WNDPROC(int(addr))`，绝不能 `WNDPROC(c_void_p)`。
  已沉淀为技能 `tkinter-windows-dragdrop` 的修正要点（若技能里还是旧写法要去更新）。

## 第四次失败：`此时不应有then`（echo 括号内的括号陷阱）

用户双击仍报 `此时不应有then`。根因：`.bat` 的「未找到 Python」分支写成
`if not defined RUN ( ... echo (tick "Add python.exe to PATH" during install), then run: ... )`。
**在 `if (...)` 括号内，以 `echo (` 开头会让 cmd 把 `(` 当成命令分组开头**，于是把
`(tick ... install), then run:` 当成分组命令解析，`then` 不是合法命令 → 报 `此时不应有then`。
且 cmd 在**解析整个括号块时**就报错（无论 RUN 是否已定义），所以双击立刻失败、根本走不到启动。

### 修复
把该分支从「括号内 echo」改为 `if not defined RUN goto :notfound`，`:notfound` 标签块放
在 `:done` 之前，并将提示语里的括号去掉（`(tick ...)` → `Tick ...`），避免任何 `echo (`。
其余（PATH 探测 / 目录探测 / `start "ExcelDiff"` 非空标题）保持不变。

### 验证
- 纯 ASCII（0 非 ASCII、无 BOM）✅
- python subprocess 跑 .bat（start 行换成 echo 占位）：rc=0、无 `此时不应有` 报错，
  正常检测到 `RUN="py"` 且 `GUI="D:\WK\N CRT\Excel对比工具\gui.py"` ✅
- 结论：启动失败四类根因已全部修完（PATH、真崩、`echo` 中文乱码、start 空标题、echo 括号陷阱）。
- 通用规则：`.bat` 里**永远不要写 `echo (` 或括号内的 `echo (...)`**；带提示的失败分支用
  `goto` 跳到括号外的标签块再 echo。
