# 2026-11-02 工作日志

## 炮孔报告汇总按矿段换品位分级（v1.13）

### 问题
中心矿段汇总"少一档"：人工成果 `0.500-0.800 / 0.800-1.000 / 1.000-999.000`，
程序出来只有 `0.500-1.000`（0.55 / 0.75 / 0.90 全并进去）。

根因：`excel_tools/src/blast_report/schema.py` 的 `GRADE_BANDS` 写死金斗山五档，
`by_total.collect_total_blocks()` 反推档位时直接调 `band_of_grade(grade)`，与"选的哪个矿段"无关。

### 改法
* 新增 `excel_tools/config/grade_profiles.json`：`edges`（分界值）+ `keywords`（认矿段），
  档位名按 `%.3f-%.3f` 自动生成；`jindoushan` / `center` 两套，`default=jindoushan`。
* 新增 `src/blast_report/profiles.py`：载入/校验（坏配置回落内置并告警）、
  `GradeProfile.band_of()`（左闭右开）、`resolve_profile()`（手动 > 路径关键字 > 源报告档位 > 默认）。
* `schema.band_of_grade(值, 分级)`、`by_total` 收 `profile`、`builder.MergeOptions.grade_profile/grade_config`，
  `merge_reports` 返回里加了 `grade_profile(_name/_reason/_source)` / `grade_bands` / `warnings`。
* CLI `--grades` / `--grade-config`；GUI「汇总方式与品位分级」加矿段下拉框，日志打 `[分级]` + 告警。
* `naming.guess_title()` 顺手修：平台标签已带矿段名（分级配置的 keywords）就不再补"北部山头"。

### 口径
* 边界一律**下限含、上限不含**；相邻档共用分界值 → 不重叠不留缝（自检逐 0.001 扫过）。
* 低于工业品位下限：金斗山（下限 0）贴最低档不变；中心矿段（下限 0.5）单列 `<0.500` 排最后 + 告警。

低于下限、配置容错、真实 3580 报告档位核对）；`test_by_total` 14/14、`test_formats` 25/25、`test_locks` 13/13 未变。
