## 修复：南部山头那套「扩展名与真实格式相反」导致 --daily 直接报错

### 现象（用户贴的两行）
```

[失败] 炮孔数据库 (.xls)：formatting_info=True not yet implemented
```

### 定位过程（值得复用）
1. 先在 `D:\WK\N CRT` 里按魔数扫所有 `1、*` / `*报告*` —— **没有**名实不符的，说明不是北部山头；
2. 扩大到 `D:\WK` + 桌面，找到第二个数据树
   `D:\WK\26.09.22南部山头二号矿体\南部山头新增Ⅱ号矿体资料\二次圈矿资料\南部山头2026\`；
3. 那套的平台级目录里 `1、…炮孔数据表.xlsx` 是**真 xlsx**、`3、…数据库矿块报告-2026年综合表.xls`
   是**真 BIFF** —— 与北部山头正好相反，两条报错同时被解释；
4. 注意：南部山头**单日目录**里反而是正常的（库 .xls / 报告 .xlsx），
   两个错都出在**总表侧**。

### 南部山头数据结构（两套并存，命名不同）
* 平台目录：`1、<平台>平台炮孔数据表.xlsx` / `2、…炮孔数据库.mdb` / `3、…数据库矿块报告-<年>综合表.xls`
  / `5、…二次圈矿矿块图-2026综合图.dwg` / `6、<平台>平台二次圈矿矿块图` / `7、单日数据`
* db 的 xlsx 多一张表 `每日坐标`（**没有表头行**，且 E 列是公式 `=D1-3960`）；
  三张业务表 `定位表/测斜表/pit_blast` 列名与北部山头完全一致
* mdb 结构与北部山头一致（3 张业务表 + 3 张 3DMine 元数据表）
* 综合报告 `.xls` 有 4 个 sheet：`每日 / 总表 / 每日合计 / 2026年`，
  报告块堆在**第 1 张 `每日`**，7~8 列（多 `24年爆破/25年出矿`），档位写法 `2.500-999.000` 等；
  块尾用 `总计` 而不是 `合计`
* 工程号前缀是 `NS-`（北部山头是 `BS-`）

### 改法
* 新增 `src/excel_core/filetype.py`：`sniff()` 读文件头
  （`PK\x03\x04`→xlsx，`D0CF11E0…`→xls），**扩展名完全不参与判断**
* `db_xls.py`：读取按真实格式分派；新增 xlsx 总表写入（openpyxl 原地追加 + 借最后一行样式）
* `report_xlsx.py`：新增 `_merge_into_xls`——块写到第一张表，公式用 `xlwt.Formula` + 正则平移行号，
  合并单元格 `write_merge` 重建，样式**借总表里同类行**（title/header/subtotal/total/data 各借各的）
* `check_totals` 改成"先读成二维值网格再比"，两种格式通用
* `schema.is_report_title()` 兼容「炮孔数据报告 / 炮孔数据库报告 / 矿块报告」；
  单日报告文件名匹配放宽；工程号前缀 `[A-Z]{2,3}-`
* 新自检 `tests/test_formats.py` **26 项**；`accept_all.py` 的 Excel 自检 3 项 → 4 项

### ⚠️ 已知副作用（必须记住）
xlsx 总表里的公式（`每日坐标` 的 `=D1-3960`，108 个）在 **openpyxl 保存后缓存值会被清空**。
公式还在，文件设了 `fullCalcOnLoad=True`（打开会重算），但**不开 Excel 直接读缓存值**的工具会读到空。
工具现在会在日志里给"[提示]"。BIFF 总表（xlutils 路径）不受影响。
→ 以后凡是 openpyxl 保存别人做的工作簿，都要考虑这条。
