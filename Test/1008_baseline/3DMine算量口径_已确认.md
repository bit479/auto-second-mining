## 一、单元几何

每个炮孔一个 Voronoi 单元；单元被**垂直拉伸成棱柱**：顶面在高程 = 孔口高程 R，
底面 = 顶面 − `gradeLenght`。属性串样例：

```
Au,0.67,gradeLenght,11.000,holepos,470095.710000 4349760.480000 3941.270000,
```

## 二、口径（已用 12 个面逐块复算，全部精确命中）

```
每孔 gradeLenght = round(该孔孔深, 0)           # 11 或 12，取整米
单元体积 = 单元面积 × 该孔 gradeLenght
矿块体积 = Σ 单元体积
矿块重量 = 矿块体积 × 2.7                      # 容重
矿块平均品位 = Σ(gradeLenght × 孔品位) / Σ(gradeLenght)   # 品位长度加权，与面积无关
矿块金属量(百克) = 矿块重量 × 平均品位 / 100
```

其中**孔品位取图上显示的 2 位小数值**（如 0.8662 记 0.87）。

## 四、仍未确定的一项

Voronoi 单元的**裁剪边界（爆区边界）**未知：

- 未裁剪时边界孔的单元会无限大（我算的 50 孔 Voronoi 单元面积合计 2×10¹³ m²）；
- 按 50 孔凸包裁剪时，体号1 只剩 28.29 m²（3DMine 是 64.9177 m²），说明 3DMine 的爆区边界比 50 孔凸包更大；
- 12 个单元面积合计 344.96 m²，而这 12 孔自身凸包只有 175.74 m²。

### 结论

既然体积/品位口径已经完全确定，**剩下的只是"单元边界从哪来"**。
这正好是走 B 方案（3DMine 原生宏通道）的理由：让 3DMine 自己生成 Voronoi 单元，
脚本只负责读单元面积 + gradeLenght 出报告与图件，不必再猜爆区边界。
